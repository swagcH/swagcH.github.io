# 背景

学完第一个 `Hello World` 之后，我开始系统学习 Java 的基础语法。刚开始觉得数据类型应该不难，因为之前学 C 语言的时候也接触过 `int`、`char`、`float` 这些类型。

但是真正写 Java 代码时，我发现 Java 的类型系统比 C 语言更严格。变量必须先声明类型，类型之间不能随便混用，很多转换都需要明确写出来。

这几天练习的时候，我还遇到了两个很容易忽略的问题：一个是 `int` 运算溢出，另一个是 `float` 和 `double` 做小数计算时出现精度丢失。看起来只是基础知识，但如果不弄清楚，以后写业务代码肯定会踩坑。

# 问题

我目前遇到的问题主要有这几个：

- 整数运算结果和预期不符（int溢出）
- float和double计算金额时精度丢失
- int和Integer傻傻分不清
- 自动类型转换和强制类型转换的规则记不住

其中最让我困惑的是：明明代码没有报错，运行结果却是错的。比如两个很大的 `int` 相加，结果可能变成负数；两个小数相加，结果也可能不是我以为的 `0.3`。

# 分析

Java 里常用的整数类型是 `int`，但是 `int` 的范围并不是无限大，它的范围大约是 ±21 亿，也就是 `-2147483648` 到 `2147483647`。如果超过这个范围，就会发生溢出。大数运算应该使用 `long`，如果数字特别大，还需要使用 `BigInteger`。

浮点数的问题也比较典型。`float` 和 `double` 采用 IEEE 754 标准，它们在底层是用二进制表示小数的，所以无法精确表示某些十进制小数，比如 `0.1`、`0.2`。因此金额计算不能使用 `float` 或 `double`，应该使用 `BigDecimal`。

另外，`int` 是基本类型，而 `Integer` 是包装类。基本类型保存的是具体的数值，包装类是对象。Java 5 以后支持自动装箱和自动拆箱，所以平时写代码时它们看起来可以互相转换，但本质上不是一回事。

类型转换的规则可以简单理解为：小类型自动转大类型，大类型转小类型需要强制转换，而且可能丢失精度。

# 解决方案

## 8种基本类型的完整表格

Java 一共有 8 种基本类型，可以分成整数、浮点数、字符和布尔四类。

![Java数据类型分类](/images/posts/2018/java-types-1.svg)

| 类型 | 字节数 | 范围 | 默认值 |
| --- | ---: | --- | --- |
| byte | 1 | -128 ~ 127 | 0 |
| short | 2 | -32768 ~ 32767 | 0 |
| int | 4 | -2147483648 ~ 2147483647 | 0 |
| long | 8 | -9223372036854775808 ~ 9223372036854775807 | 0L |
| float | 4 | 约 ±3.4E38，有效位约 6~7 位 | 0.0f |
| double | 8 | 约 ±1.7E308，有效位约 15 位 | 0.0d |
| char | 2 | 0 ~ 65535 | '\u0000' |
| boolean | 1位或不确定，JVM未明确规定 | true / false | false |

下面是 8 种基本类型的声明方式和取值范围演示：

```java
public class PrimitiveTypeDemo {
    public static void main(String[] args) {
        byte byteValue = 127;
        short shortValue = 32767;
        int intValue = 2147483647;
        long longValue = 9223372036854775807L;
        float floatValue = 3.14F;
        double doubleValue = 3.141592653589793;
        char charValue = 'A';
        boolean booleanValue = true;

        System.out.println("byte范围：" + Byte.MIN_VALUE + " ~ " + Byte.MAX_VALUE);
        System.out.println("short范围：" + Short.MIN_VALUE + " ~ " + Short.MAX_VALUE);
        System.out.println("int范围：" + Integer.MIN_VALUE + " ~ " + Integer.MAX_VALUE);
        System.out.println("long范围：" + Long.MIN_VALUE + " ~ " + Long.MAX_VALUE);
        System.out.println("float范围：" + Float.MIN_VALUE + " ~ " + Float.MAX_VALUE);
        System.out.println("double范围：" + Double.MIN_VALUE + " ~ " + Double.MAX_VALUE);
        System.out.println("char示例：" + charValue);
        System.out.println("boolean示例：" + booleanValue);
    }
}
```

这里要注意，`long` 类型的字面量后面最好加 `L`，`float` 类型的字面量后面要加 `F`，否则 Java 默认会把小数当成 `double`。

## int溢出演示代码

`int` 超过最大值后不会自动报错，而是会绕回负数，这一点刚开始看很反直觉。

```java
public class IntOverflowDemo {
    public static void main(String[] args) {
        int max = Integer.MAX_VALUE;
        int overflow = max + 1;

        System.out.println("int最大值：" + max);
        System.out.println("int最大值 + 1：" + overflow);

        long correctResult = (long) max + 1;
        System.out.println("转成long后再计算：" + correctResult);
    }
}
```

输出结果中，`Integer.MAX_VALUE + 1` 会变成 `Integer.MIN_VALUE`。所以如果参与运算的数字可能超过 `int` 范围，就要提前使用 `long`。

如果数字比 `long` 还大，就要考虑 `BigInteger`：

```java
import java.math.BigInteger;

public class BigIntegerDemo {
    public static void main(String[] args) {
        BigInteger a = new BigInteger("999999999999999999999999999999");
        BigInteger b = new BigInteger("888888888888888888888888888888");
        BigInteger sum = a.add(b);

        System.out.println(sum);
    }
}
```

## float精度丢失代码

下面这个例子是我印象很深的一个坑：

```java
public class FloatPrecisionDemo {
    public static void main(String[] args) {
        float a = 0.1F;
        float b = 0.2F;
        double c = 0.1;
        double d = 0.2;

        System.out.println(a + b);
        System.out.println(c + d);
    }
}
```

结果不一定是准确的 `0.3`，因为二进制浮点数不能精确表示某些十进制小数。

## BigDecimal解决金额计算的完整示例

金额计算应该使用 `BigDecimal`，而且创建 `BigDecimal` 时尽量使用字符串，不要直接传入 `double`。

```java
import java.math.BigDecimal;
import java.math.RoundingMode;

public class BigDecimalMoneyDemo {
    public static void main(String[] args) {
        BigDecimal price = new BigDecimal("19.90");
        BigDecimal count = new BigDecimal("3");
        BigDecimal discount = new BigDecimal("5.00");

        BigDecimal total = price.multiply(count).subtract(discount);
        BigDecimal average = total.divide(count, 2, RoundingMode.HALF_UP);

        System.out.println("总金额：" + total);
        System.out.println("平均金额：" + average);
    }
}
```

这个例子里，`multiply` 是乘法，`subtract` 是减法，`divide` 是除法。除法一定要注意指定保留位数和舍入方式，否则遇到除不尽的情况可能会抛异常。

## 引用类型和基本类型的区别对比

Java 的数据类型可以分成基本类型和引用类型。

| 对比项 | 基本类型 | 引用类型 |
| --- | --- | --- |
| 保存内容 | 直接保存值 | 保存对象的引用地址 |
| 是否为对象 | 不是对象 | 是对象 |
| 默认值 | 例如 int 是 0，boolean 是 false | null |
| 常见类型 | byte、short、int、long、float、double、char、boolean | 类、接口、数组、枚举、注解 |
| 方法调用 | 不能直接调用方法 | 可以调用对象方法 |
| 泛型使用 | 不能直接作为泛型类型 | 可以作为泛型类型 |

比如 `int` 和 `Integer` 就是最常见的一组对比：

```java
public class IntIntegerDemo {
    public static void main(String[] args) {
        int primitiveValue = 10;
        Integer wrapperValue = Integer.valueOf(10);

        System.out.println(primitiveValue);
        System.out.println(wrapperValue.toString());
    }
}
```

`int` 只是一个数值，`Integer` 是一个对象，所以 `Integer` 可以调用方法，也可以放进集合里。

## 自动类型转换规则图示

Java 中常见的自动类型转换顺序可以记成下面这样：

```text
byte -> short -> int -> long -> float -> double
char -> int -> long -> float -> double
```


小范围类型赋值给大范围类型时，可以自动转换：

```java
public class AutoConvertDemo {
    public static void main(String[] args) {
        byte byteValue = 10;
        int intValue = byteValue;
        long longValue = intValue;
        double doubleValue = longValue;

        char charValue = 'A';
        int charCode = charValue;

        System.out.println(doubleValue);
        System.out.println(charCode);
    }
}
```

这里 `byte` 可以自动转成 `int`，`int` 可以自动转成 `long`，`long` 也可以自动转成 `double`。

## 强制类型转换示例及注意事项

大范围类型转成小范围类型时，需要强制转换：

```java
public class ForceConvertDemo {
    public static void main(String[] args) {
        double doubleValue = 3.99;
        int intValue = (int) doubleValue;

        int largeValue = 130;
        byte byteValue = (byte) largeValue;

        System.out.println("double转int：" + intValue);
        System.out.println("int转byte：" + byteValue);
    }
}
```

`double` 转成 `int` 后，小数部分会被直接截断，不会四舍五入。`130` 转成 `byte` 后也不是 `130`，因为 `byte` 的范围只有 `-128 ~ 127`，超出范围会发生溢出。

## 自动装箱拆箱的示例及IntegerCache陷阱

自动装箱就是基本类型自动转成包装类，自动拆箱就是包装类自动转成基本类型。

```java
public class BoxingDemo {
    public static void main(String[] args) {
        int primitiveValue = 100;
        Integer boxedValue = primitiveValue;
        int unboxedValue = boxedValue;

        System.out.println(boxedValue);
        System.out.println(unboxedValue);
    }
}
```

但是 `Integer` 有一个缓存范围，默认是 `-128 ~ 127`。这个地方很容易让人误以为 `==` 比较的是数值，其实对象之间的 `==` 比较的是引用地址。

```java
public class IntegerCacheDemo {
    public static void main(String[] args) {
        Integer a = 127;
        Integer b = 127;
        Integer c = 128;
        Integer d = 128;

        System.out.println(a == b);
        System.out.println(c == d);
        System.out.println(c.equals(d));
    }
}
```

`a == b` 是 `true`，因为 `127` 在缓存范围内。`c == d` 是 `false`，因为 `128` 默认不在缓存范围内，会创建不同的对象。比较包装类的数值时，应该使用 `equals`，不要使用 `==`。

另外，自动拆箱时如果包装类是 `null`，会抛出空指针异常：

```java
public class UnboxingNullDemo {
    public static void main(String[] args) {
        Integer value = null;
        int result = value;

        System.out.println(result);
    }
}
```

这段代码编译能通过，但运行时会报 `NullPointerException`。所以包装类拆箱前要特别注意是否为 `null`。

# 总结

学完这部分之后，我感觉 Java 的数据类型虽然看起来基础，但细节很多。尤其是类型范围、精度问题、包装类和类型转换，如果只靠直觉写代码，很容易出现隐藏 bug。

我的阶段性总结是：

- Java是强类型语言，类型安全比C更严格
- 金额计算永远不要用float/double
- 注意基本类型和包装类的区别
- 类型转换要小心精度丢失

以后写代码时，我会尽量先想清楚变量的范围和用途，再决定使用哪种类型。对于金额这种对精度要求很高的数据，一开始就应该使用 `BigDecimal`，不要等出问题后再改。
