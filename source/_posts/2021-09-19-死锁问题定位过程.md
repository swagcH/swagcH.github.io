# 背景

死锁定位需要保存现场，优先抓取线程 dump，而不是盲目重启。


# 问题

```text
接口无响应，CPU 正常，部分请求一直 pending
```

```bash
jps -l
jstack $(pgrep java) > /tmp/deadlock.jstack
grep -n "deadlock" /tmp/deadlock.jstack
```

# 分析

```text
Found one Java-level deadlock:
"thread-a" waiting to lock monitor 0x001
"thread-b" waiting to lock monitor 0x002
```

```java
synchronized (orderLock) {
    synchronized (stockLock) {
        // update order and stock
    }
}
```

# 解决方案

```java
String lockKey = orderId.compareTo(stockId) < 0
    ? orderId + ":" + stockId
    : stockId + ":" + orderId;

synchronized (lockKey.intern()) {
    updateOrder();
    updateStock();
}
```

```text
原则：统一加锁顺序、缩小锁范围、避免锁内远程调用
```

# 总结

```text
复盘要点：
1. 先保留现场，再尝试恢复
2. 先确认影响范围，再判断根因
3. 日志、监控、配置、代码需要串起来看
4. 修复动作必须可验证
5. 故障结束后补充检查项和自动化规则
```
