# 背景

2018年双十一刚过，项目终于要部署上线了。公司买了两台阿里云ECS服务器，操作系统是CentOS 7.4。作为一个从大学到现在一直在Windows环境下写代码的.NET程序员，听到"部署到Linux服务器"这几个字时，内心是拒绝的。

之前对Linux的印象停留在"黑乎乎的命令行窗口，一堆看不懂的英文字母"。但项目不等人，硬着头皮上吧。花了大概两周时间边查边练，把日常运维常用的Linux命令过了一遍，这篇文章就是这段时间的学习笔记。

# 问题

刚接手Linux服务器时，遇到了一堆"小白问题"，说来有点丢人但确实很真实：

**1. 文件权限看不懂**

`ls -l` 输出了一堆 `drwxr-xr-x` 这样的东西，完全不知道什么意思。想给文件加执行权限，百度了半天才找到 `chmod 777`，但到底什么是"777"也说不清楚。

**2. vim编辑器不会用**

用 `vi` 打开文件后，发现打不了字，想退出却退不出来，最后直接关了终端。后来才知道 vim 有三种模式，退出要用 `:q`。

**3. 进程查不到**

程序跑起来后不知道在哪看，Windows 有任务管理器，Linux 呢？程序挂了也不知道为什么挂的。

**4. 磁盘满了不知道清哪里**

有一天数据库写不进去了，排查半天发现是磁盘满了。但日志文件、临时文件散落在各个目录，不知道从哪里开始清理。

**5. 日志文件太大查看困难**

Java 应用的日志文件动辄几百兆甚至几个G，用记事本打开直接卡死。想查最新的报错信息，总不能把整个文件拖下来吧。

**6. 端口被占用不知道怎么查**

Tomcat 启动报错 `Address already in use`，知道是端口被占了，但不知道被哪个程序占了，也不知道怎么杀掉它。

# 分析

遇到这些问题后，我花了一些时间理解了 Linux 的几个核心概念，这些概念是后续学习命令的基础。

### Linux 一切皆文件

这是 Linux 最核心的设计哲学。普通文件是文件，目录是文件，设备是文件，甚至是进程信息、网络连接都被抽象成了文件。理解了这一点，就能理解为什么 Linux 有那么多文件操作命令了。

### 权限的 rwx 表示法

`rwx` 分别代表：
- `r`（read）：读取权限，值为 4
- `w`（write）：写入权限，值为 2
- `x`（execute）：执行权限，值为 1

权限分三组，每组三个字符：**所有者/所属组/其他人**。所以 `rwxr-xr-x` 表示：所有者可读写执行，所属组可读执行，其他人可读执行。

而 `chmod 755` 中的 755，就是用数字表示的权限：
- 7 = 4+2+1 = rwx（所有者）
- 5 = 4+0+1 = r-x（所属组）
- 5 = 4+0+1 = r-x（其他人）

### vim 的三种模式

刚接触 vim 时觉得这编辑器反人类，理解了三种模式后就豁然开朗了：

- **命令模式**：刚进入 vim 时的模式，可以复制粘贴删除，但**不能输入文字**
- **插入模式**：按 `i` 进入，这个模式才能正常打字
- **末行模式**：按 `:` 进入，用来保存退出、搜索替换

三种模式切换搞明白后，vim 就好用多了。

### 进程管理思路

Linux 的进程管理不像 Windows 那样可视化，但命令行的方式其实更灵活：
- `ps` 查看静态进程快照
- `top` 查看动态进程信息（相当于任务管理器）
- `kill` 发送信号给进程

### 磁盘查看思路

- `df` 从宏观角度查看磁盘整体使用情况
- `du` 从微观角度查看具体目录/文件占用空间

### 日志查看三板斧

大文件用编辑器打开是不现实的，Linux 提供了三个利器：
- `tail`：从尾部看，适合看最新的日志
- `grep`：按关键字过滤，适合搜索特定错误
- `less`：分页查看，适合在文件中上下翻阅

### 端口查看思路

- `netstat`：查看网络连接状态
- `lsof`：查看打开的文件（一切皆文件，网络连接也是文件）

# 解决方案

下面按场景分类整理常用命令，每个分类给出常用命令和实际运维示例。

### 一、文件目录操作

```bash
# 查看目录内容
ls                    # 列出当前目录文件
ls -l                 # 详细列表（显示权限、大小、修改时间）
ls -a                 # 显示隐藏文件（以.开头的文件）
ls -lh                # 以人类可读方式显示大小（K、M、G）

# 目录切换
cd /usr/local         # 进入指定目录
cd ~                  # 进入home目录
cd -                  # 返回上一个目录
cd ..                 # 返回上级目录

# 创建和删除
mkdir myapp           # 创建目录
mkdir -p a/b/c        # 递归创建多级目录
touch README.md       # 创建空文件
cp app.conf app.conf.bak    # 复制文件
cp -r webapp/ webapp_bak/   # 递归复制目录
mv app.conf /tmp/     # 移动文件
mv oldname newname    # 重命名文件
rm temp.txt           # 删除文件（不会进回收站，直接删）
rm -rf logs/          # 递归强制删除目录（慎用！）

# 查找文件
find / -name "*.log"                   # 从根目录找所有.log文件
find /var/log -mtime -7                # 查找7天内修改过的文件
find . -size +100M                     # 查找当前目录下大于100M的文件
find . -name "*.tmp" -exec rm {} \;    # 查找并删除临时文件
```

**运维场景：查找并清理大文件**

```bash
# 查找根目录下大于500M的文件，按大小排序
find / -type f -size +500M -exec ls -lh {} \; 2>/dev/null | awk '{print $5, $NF}' | sort -rh

# 清理7天前的日志文件
find /var/log/myapp/ -name "*.log" -mtime +7 -exec rm {} \;
```

### 二、文件查看与搜索

```bash
# 查看文件内容
cat README.md               # 显示整个文件（适合小文件）
cat -n app.log              # 显示行号
less app.log                # 分页查看（按空格翻页，按q退出）
head -20 app.log            # 查看前20行
tail -100 app.log           # 查看后100行
tail -f app.log             # 实时跟踪文件新增内容（看日志神器！）

# 搜索文件内容
grep "ERROR" app.log                      # 在文件中搜索关键字
grep -i "error" app.log                   # 忽略大小写搜索
grep -r "NullPointerException" /logs/     # 递归搜索目录下所有文件
grep -n "ERROR" app.log                   # 显示匹配行及其行号
grep -c "ERROR" app.log                   # 统计匹配行数
grep -A5 "ERROR" app.log                  # 显示匹配行及其后5行
grep -B5 "ERROR" app.log                  # 显示匹配行及其前5行
grep -C5 "ERROR" app.log                  # 显示匹配行及其前后各5行
```

**运维场景：查看日志中的错误信息**

```bash
# 查看今天出现的所有ERROR及上下文
tail -10000 app.log | grep -C5 "ERROR" | less

# 统计各错误类型出现次数
grep -o "ERROR \[.*\]" app.log | sort | uniq -c | sort -rn

# 查看某个时间段内的日志
grep "2018-11-18 10:" app.log | less
```

### 三、权限管理

```bash
# 修改权限
chmod 755 script.sh          # 设置权限为rwxr-xr-x
chmod +x script.sh           # 给文件加执行权限
chmod -R 644 html/           # 递归设置目录下所有文件权限

# 修改所有者
chown admin app.log          # 修改文件所有者为admin
chown admin:admin app.log    # 同时修改所有者和所属组
chown -R admin:admin /app/   # 递归修改目录下所有文件所有者

# 查看文件权限
ls -l                        # 查看文件的权限信息
stat app.conf                # 查看文件的详细状态（包括权限）
```

**运维场景：部署项目后修复权限**

```bash
# 项目部署后的权限设置
chown -R www:www /var/www/myapp/          # 设置为www用户
find /var/www/myapp/ -type f -exec chmod 644 {} \;   # 文件设置为644
find /var/www/myapp/ -type d -exec chmod 755 {} \;   # 目录设置为755
```

### 四、用户管理

```bash
# 创建用户
useradd tom                    # 创建用户tom
passwd tom                     # 设置用户tom的密码
useradd -m -g www dev          # 创建用户dev，加入www组并创建home目录

# 查看用户
who                            # 查看当前登录用户
w                              # 查看更详细的登录信息
id tom                         # 查看用户tom的UID和GID
groups                         # 查看当前用户所属组

# 切换用户
su - tom                       # 切换到tom用户
sudo command                   # 以root身份执行命令
```

### 五、进程管理

```bash
# 查看进程
ps -ef                         # 查看所有进程的详细信息
ps aux                         # 查看所有进程（CPU/内存占用）
ps -ef | grep java             # 查看Java相关进程
top                            # 实时查看进程状态（按q退出）
top -bn1                       # 一次性输出top结果（适合脚本采集）

# 终止进程
kill 12345                     # 优雅终止PID为12345的进程
kill -9 12345                  # 强制杀掉PID为12345的进程
killall java                   # 杀掉所有Java进程

# 后台运行
nohup java -jar app.jar &      # 后台运行Java应用，退出终端不停止
jobs                           # 查看后台运行的任务列表
fg %1                          # 将后台任务1调回前台
```

**运维场景：重启 Java 应用**

```bash
# 完整的应用重启流程
ps -ef | grep app.jar | grep -v grep  # 先找到进程
kill 12345                             # 优雅停止
sleep 3                                # 等待3秒
nohup java -jar app.jar > app.log 2>&1 &   # 后台启动，日志重定向
tail -f app.log                       # 实时查看启动日志
```

### 六、磁盘管理

```bash
# 查看磁盘整体情况
df -h                          # 以人类可读格式查看磁盘使用情况
df -h /dev/sda1                # 查看指定分区

# 查看目录大小
du -sh /var/log/               # 查看目录总大小
du -sh *                       # 查看当前目录下每个子目录的大小
du -h --max-depth=1 /home/     # 只看一层目录的大小
du -sh /* | sort -rh           # 查看根目录下各目录大小并排序

# 磁盘空间排查
du -sh /var/log/               # 检查日志目录大小
du -sh /tmp/                   # 检查临时目录大小
du -sh /opt/                   # 检查应用目录大小
```

**运维场景：磁盘告警排查**

```bash
# 第一步：查看整体使用情况
df -h

# 第二步：找到最大的目录
du -sh /* | sort -rh | head -10

# 第三步：逐层深入找到大文件
du -sh /var/* | sort -rh | head -5
du -sh /var/log/* | sort -rh | head -5

# 第四步：清理日志
find /var/log/ -name "*.log" -mtime +30 -exec rm {} \;
```

### 七、网络管理

```bash
# 查看端口
netstat -tlnp                  # 查看所有TCP监听端口及对应进程
netstat -tlnp | grep 8080      # 查看8080端口被谁占用
netstat -an | grep ESTABLISHED # 查看已建立的连接

# lsof 查看端口（更直观）
lsof -i :8080                  # 查看8080端口被哪个进程占用
lsof -i tcp                    # 查看所有TCP连接
lsof -p 12345                  # 查看进程12345打开了哪些文件

# 网络连通性
ping -c 4 baidu.com            # 测试网络连通性，发4个包
curl -I http://localhost:8080   # 查看HTTP响应头
telnet 192.168.1.1 3306        # 测试端口是否可达

# DNS相关
nslookup www.baidu.com         # 域名解析查询
host www.baidu.com             # 简化的域名查询
```

**运维场景：端口被占用了怎么办**

```bash
# 场景：Tomcat启动报错 Address already in use

# 步骤1：查看端口被谁占了
netstat -tlnp | grep 8080
# 输出：tcp6  0  0 :::8080  :::*  LISTEN  12345/java

# 步骤2：确认是这个进程，可以选择：
# 方案A：杀掉占用进程
kill 12345

# 方案B：或者换个端口启动，如果杀不掉的话
```

### 八、压缩解压

```bash
# tar 打包/解包
tar -czf myapp.tar.gz /var/www/myapp/      # 打包并压缩为.tar.gz
tar -xzf myapp.tar.gz                      # 解压.tar.gz包
tar -tzf myapp.tar.gz                      # 查看包内容列表（不实际解压）
tar -xjf myapp.tar.bz2                     # 解压.tar.bz2包

# gzip压缩
gzip app.log                               # 压缩文件（生成app.log.gz）
gzip -d app.log.gz                         # 解压缩
gunzip app.log.gz                          # 同上，解压缩

# zip（跨平台常用）
zip -r myapp.zip /var/www/myapp/           # 压缩目录
unzip myapp.zip -d /tmp/                   # 解压到指定目录
```

**运维场景：备份项目并压缩**

```bash
# 备份项目目录，按日期命名
tar -czf myapp_$(date +%Y%m%d_%H%M%S).tar.gz /var/www/myapp/

# 解压到指定目录
tar -xzf myapp_20181118.tar.gz -C /tmp/restore/
```

### 十、组合命令与管道

管道 `|` 是 Linux 命令的精髓，它把前一个命令的输出作为后一个命令的输入，像流水线一样：

```bash
# 管道的基本使用
ps -ef | grep java              # 在进程列表中搜索Java进程
netstat -tlnp | grep 80         # 在网络连接中搜索80端口
cat app.log | grep ERROR | head -20    # 在日志中找错误，只看前20条
ls -l | grep "^d"               # 只列出目录（行首为d的是目录）
ls -l | awk '{print $5, $NF}'   # 只显示文件大小和名称
ls -l | sort -k5 -rn | head -5  # 列出当前目录最大的5个文件

# 输出重定向
echo "Hello" > README.md        # 覆盖写入文件
echo "World" >> README.md       # 追加写入文件
ls /nonexist 2> error.log       # 将错误信息重定向到文件
java -jar app.jar > app.log 2>&1 &    # 标准输出和错误都输出到日志文件

# 实际运维组合命令示例
# 找出占用CPU最高的进程
top -bn1 | head -20

# 统计日志中各IP的访问次数
cat access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head -10

# 批量替换配置文件中的IP
find /app/config/ -name "*.properties" | xargs sed -i 's/192.168.1.100/192.168.2.100/g'

# 压缩30天前的日志
find /var/log/myapp/ -name "*.log" -mtime +30 | xargs gzip
```

# 总结

两周的密集使用下来，从最初在终端面前手足无措，到能比较顺畅地完成日常运维操作，有一些心得想分享给和我一样从 Windows 转 Linux 的同学：

**1. Linux 命令不需要死记硬背**

命令太多了，没有人能记住所有命令的所有参数。关键是要知道**解决某个问题可以用什么命令**，具体的参数用法用 `man` 或 `--help` 现查就行：

```bash
man ls                 # 查看ls的完整手册（按q退出）
ls --help              # 查看ls的快速帮助（推荐，更直观）
```

我基本上每天都要查几次 `tar` 的参数——"压缩是 `-czf` 还是 `-xzf` 来着"——这很正常，查多了自然就记住了。

**2. 管道是 Linux 的精髓**

管道 `|` 让我真正感受到了 Linux 命令行的威力。单个命令功能有限，但组合起来能做很复杂的事情。就像搭积木一样，把一个个小命令拼起来解决问题。

```bash
# 学会了管道之后，就能写出这样的命令来解决复杂问题
ps -ef | grep java | grep -v grep | awk '{print $2}' | xargs kill -9
```

**3. 多用 alias 简化常用操作**

把常用的长命令设成别名，能省不少事：

```bash
alias ll='ls -alh'
alias g='grep --color=auto'
alias ..='cd ..'
# 写入 .bashrc 后永久生效
echo "alias ll='ls -alh'" >> ~/.bashrc
source ~/.bashrc
```

**4. 小心 rm -rf**

`rm -rf` 是 Linux 上最危险的命令之一。没有回收站，没有二次确认，文件直接就没了。使用前一定要确认路径是否正确，尤其是在 root 用户下。建议养成习惯：

- 执行 `rm` 前先 `ls` 确认一下
- 重要的文件先备份
- 用 `mv` 代替 `rm`，把文件移到 `/tmp/` 目录（系统定期会清理）

**5. 多敲多练是最好的学习方式**

读十遍这篇文章不如自己在服务器上敲一遍。我在自己的电脑上装了虚拟机，把上面的命令都练了一遍。遇到实际运维问题时，先百度/Google，解决了就记下来，慢慢就形成了自己的命令速查手册。

现在回头看，Linux 命令行没有想象的那么可怕。它只是和 Windows 不同的另一种工作方式，适应了之后甚至会喜欢上这种高效的操作。希望这篇文章对同样刚接触 Linux 的你有所帮助。
