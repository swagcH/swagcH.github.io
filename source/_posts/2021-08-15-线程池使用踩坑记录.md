# 背景

线程池问题往往不是线程不够，而是队列、任务耗时和拒绝策略设计不合理。

```text
记录类型：故障排查
记录年份：2021
记录方式：现象、命令、日志、代码、配置、结论
```

# 问题

```text
active=32 poolSize=32 queueSize=10000 completed=1200
接口响应时间从 200ms 上升到 6s
CPU 不高，任务堆积明显
```

```java
Executors.newFixedThreadPool(32);
```

# 分析

```text
问题：
1. 队列过大，流量尖峰时延迟被隐藏
2. 无拒绝策略监控
3. 任务内部还有远程调用
4. 线程池参数没有按业务隔离
```

# 解决方案

```java
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    16,
    32,
    60,
    TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(500),
    new ThreadPoolExecutor.CallerRunsPolicy()
);
```

```text
监控指标：activeCount、queueSize、completedTaskCount、rejectCount
```

# 总结

```text
复盘要点：
1. 先保留现场，再尝试恢复
2. 先确认影响范围，再判断根因
3. 日志、监控、配置、代码需要串起来看
4. 修复动作必须可验证
5. 故障结束后补充检查项和自动化规则
```
