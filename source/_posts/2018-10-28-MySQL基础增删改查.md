# 背景

学完JDBC之后，我意识到一个很严重的问题——我一直在“照着写”SQL，却从来没有真正理解过每条SQL背后的含义。JDBC教会了我怎么用Java连接数据库、怎么执行SQL、怎么处理ResultSet，但SQL本身呢？我只会照猫画虎地写几句SELECT和INSERT，稍微复杂一点的查询就抓瞎。

这段时间我决定从头系统地学习SQL，从最基础的建表开始，到增删改查，再到多表关联、聚合函数、索引优化，一步一步把每个知识点搞清楚。这篇文章就是我在2018年10月学习MySQL基础CRUD的完整记录。

# 问题

在实际写SQL的过程中，我遇到了好几个一直没搞明白的问题：

1. **DELETE和TRUNCATE到底有什么区别？** 之前一直以为都是删数据，随便用哪个都行，结果有一次用TRUNCATE删完数据发现回不去了。
2. **GROUP BY和HAVING总是写错**，经常把过滤条件写在WHERE里，结果报错，搞不清什么时候该用WHERE、什么时候该用HAVING。
3. **多表JOIN搞不清关系**，INNER JOIN、LEFT JOIN、RIGHT JOIN到底返回什么数据，每次都要画图才能想明白。
4. **索引加了但查询还是很慢**，以为建了索引就万事大吉，结果有些查询根本没走索引。
5. **不知道什么时候该建索引**，哪些列该建、哪些不该建，完全没有概念。

# 分析

## DELETE和TRUNCATE的区别

这两个看起来都是“删数据”，但底层机制完全不同：

| 对比点 | DELETE | TRUNCATE |
| --- | --- | --- |
| 删除方式 | 逐行删除 | 清空并重建表结构 |
| SQL类型 | DML | DDL |
| 是否可回滚 | 在事务中可回滚 | 通常不可回滚 |
| 是否支持WHERE | 支持 | 不支持 |
| 自增ID | 一般不重置 | 通常会重置 |
| 执行速度 | 数据量大时较慢 | 通常更快 |

简单理解：DELETE是一行一行删，可以配合WHERE精确删除，也可以在事务中回滚；TRUNCATE更像是把表清空后重新整理，速度快，但风险也更高。

## GROUP BY和HAVING

我之前经常把聚合条件写到WHERE里，例如想查平均分大于80的学生，却写成：

```sql
SELECT student_id, AVG(score)
FROM score
WHERE AVG(score) > 80
GROUP BY student_id;
```

这肯定是不对的，因为WHERE执行时还没有分组，自然也没有AVG(score)这个结果。正确写法应该是：

```sql
SELECT student_id, AVG(score)
FROM score
GROUP BY student_id
HAVING AVG(score) > 80;
```

WHERE是在分组前过滤原始行，HAVING是在分组后过滤聚合结果。

## JOIN类型的区别

JOIN最核心的不是语法，而是先搞清楚两张表之间的关系：

- **INNER JOIN**：只返回两边都匹配的数据。
- **LEFT JOIN**：左表全部保留，右表匹配不到的地方用NULL补齐。
- **RIGHT JOIN**：右表全部保留，左表匹配不到的地方用NULL补齐。

实际开发中我感觉LEFT JOIN用得更多，因为很多时候我们会以一张主表为中心，再去关联其它明细表。

## 索引不是万能的

索引像书的目录，可以帮助数据库快速定位数据。但它不是万能药，加了索引并不代表一定快：

- 表数据量很小时，全表扫描可能更快。
- 查询返回的数据太多时，走索引反而不划算。
- 在索引列上使用函数，可能导致索引失效。
- LIKE以`%`开头时，通常无法利用普通索引。
- 字段发生隐式类型转换时，也可能导致索引失效。

## 索引应该建在什么列上

比较适合建索引的列：

- 区分度高的列，比如学生ID、手机号、身份证号。
- 经常出现在WHERE条件里的列。
- 经常用于JOIN关联的外键列。
- 经常用于ORDER BY或GROUP BY的列。

不太适合建索引的列：

- 区分度很低的列，比如性别。
- 经常更新的列，因为维护索引也有成本。
- 很少参与查询条件的列。

# 解决方案

## 准备三张表

我用学生、课程、成绩三张表来练习，关系比较清晰：一个学生可以选择多门课程，一门课程也可以被多个学生选择，成绩表负责连接学生和课程。

```sql
-- 学生表：保存学生基本信息
CREATE TABLE student (
    id INT PRIMARY KEY AUTO_INCREMENT COMMENT '学生ID',
    name VARCHAR(50) NOT NULL COMMENT '姓名',
    age INT COMMENT '年龄',
    gender VARCHAR(10) COMMENT '性别',
    major VARCHAR(50) COMMENT '专业',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8 COMMENT='学生表';

-- 课程表：保存课程基本信息
CREATE TABLE course (
    id INT PRIMARY KEY AUTO_INCREMENT COMMENT '课程ID',
    name VARCHAR(50) NOT NULL COMMENT '课程名称',
    credit INT NOT NULL COMMENT '学分'
) ENGINE=InnoDB DEFAULT CHARSET=utf8 COMMENT='课程表';

-- 成绩表：保存学生和课程的对应关系以及成绩
CREATE TABLE score (
    id INT PRIMARY KEY AUTO_INCREMENT COMMENT '成绩ID',
    student_id INT NOT NULL COMMENT '学生ID',
    course_id INT NOT NULL COMMENT '课程ID',
    score DECIMAL(5,2) COMMENT '成绩',
    exam_time DATE COMMENT '考试日期',
    CONSTRAINT fk_score_student FOREIGN KEY (student_id) REFERENCES student(id),
    CONSTRAINT fk_score_course FOREIGN KEY (course_id) REFERENCES course(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8 COMMENT='成绩表';
```

## UPDATE：修改数据

```sql
-- 修改张三的年龄
UPDATE student
SET age = 21
WHERE name = '张三';

-- 修改数据库原理课程的学分
UPDATE course
SET credit = 5
WHERE name = '数据库原理';

-- 给王五的所有成绩加5分
UPDATE score
SET score = score + 5
WHERE student_id = (
    SELECT id FROM student WHERE name = '王五'
);
```

## DELETE：删除数据

```sql
-- 删除低于60分的成绩记录
DELETE FROM score
WHERE score < 60;

-- 删除某个学生的成绩记录
DELETE FROM score
WHERE student_id = 3;

-- 删除成绩表全部数据，可配合事务回滚
DELETE FROM score;

-- 清空成绩表，不支持WHERE，风险更高
TRUNCATE TABLE score;
```

## SELECT：基础查询

```sql
-- 查询所有学生
SELECT * FROM student;

-- 只查询指定列
SELECT name, age, major FROM student;

-- 条件查询
SELECT name, age
FROM student
WHERE major = '计算机科学';

-- 模糊查询
SELECT * FROM student
WHERE name LIKE '张%';

-- 排序查询
SELECT * FROM student
ORDER BY age DESC;

-- 分页查询：从第0条开始取10条
SELECT * FROM student
LIMIT 0, 10;
```

## 多表JOIN查询

```sql
-- INNER JOIN：只查询有成绩的学生和课程
SELECT
    s.name AS student_name,
    c.name AS course_name,
    sc.score AS exam_score
FROM student s
INNER JOIN score sc ON s.id = sc.student_id
INNER JOIN course c ON sc.course_id = c.id;

-- LEFT JOIN：查询所有学生，即使学生还没有成绩也会显示
SELECT
    s.name AS student_name,
    c.name AS course_name,
    sc.score AS exam_score
FROM student s
LEFT JOIN score sc ON s.id = sc.student_id
LEFT JOIN course c ON sc.course_id = c.id;

-- RIGHT JOIN：以课程表为主，查询所有课程的选课成绩
SELECT
    s.name AS student_name,
    c.name AS course_name,
    sc.score AS exam_score
FROM student s
RIGHT JOIN score sc ON s.id = sc.student_id
RIGHT JOIN course c ON sc.course_id = c.id;
```

## 聚合函数和GROUP BY

```sql
-- 查询每个学生的平均成绩
SELECT
    s.name AS student_name,
    AVG(sc.score) AS avg_score
FROM student s
INNER JOIN score sc ON s.id = sc.student_id
GROUP BY s.id, s.name;

-- 查询平均成绩大于80分的学生
SELECT
    s.name AS student_name,
    AVG(sc.score) AS avg_score
FROM student s
INNER JOIN score sc ON s.id = sc.student_id
GROUP BY s.id, s.name
HAVING AVG(sc.score) > 80;

-- 查询每门课程的选课人数、最高分和最低分
SELECT
    c.name AS course_name,
    COUNT(sc.id) AS student_count,
    MAX(sc.score) AS max_score,
    MIN(sc.score) AS min_score
FROM course c
LEFT JOIN score sc ON c.id = sc.course_id
GROUP BY c.id, c.name;
```

## 子查询

```sql
-- 查询成绩高于全班平均分的记录
SELECT
    s.name AS student_name,
    sc.score AS exam_score
FROM student s
INNER JOIN score sc ON s.id = sc.student_id
WHERE sc.score > (
    SELECT AVG(score) FROM score
);

-- 查询选择了数据库原理课程的学生
SELECT name
FROM student
WHERE id IN (
    SELECT sc.student_id
    FROM score sc
    INNER JOIN course c ON sc.course_id = c.id
    WHERE c.name = '数据库原理'
);

-- 查询至少有一门成绩大于90分的学生
SELECT s.name
FROM student s
WHERE EXISTS (
    SELECT 1
    FROM score sc
    WHERE sc.student_id = s.id
      AND sc.score > 90
);
```

## 索引创建和使用建议

```sql
-- 给成绩表的学生ID建立索引，提升按学生查询成绩的速度
CREATE INDEX idx_score_student_id ON score(student_id);

-- 给成绩表的课程ID建立索引，提升按课程查询成绩的速度
CREATE INDEX idx_score_course_id ON score(course_id);

-- 给学生姓名建立索引，提升按姓名精确查询的速度
CREATE INDEX idx_student_name ON student(name);

-- 联合索引：适合同时按学生和课程查询成绩的场景
CREATE INDEX idx_score_student_course ON score(student_id, course_id);

-- 删除索引
DROP INDEX idx_student_name ON student;
```

联合索引要注意最左前缀原则。假设建立了`(student_id, course_id)`这个联合索引：

```sql
-- 可以使用联合索引
SELECT * FROM score WHERE student_id = 1;

-- 可以使用联合索引
SELECT * FROM score WHERE student_id = 1 AND course_id = 2;

-- 通常不能完整使用这个联合索引，因为跳过了最左边的student_id
SELECT * FROM score WHERE course_id = 2;
```

## EXPLAIN查看执行计划

EXPLAIN可以帮助我判断SQL到底有没有走索引，不能只靠感觉猜。

```sql
-- 查看按学生ID查询成绩的执行计划
EXPLAIN SELECT * FROM score WHERE student_id = 1;

-- 查看JOIN查询的执行计划
EXPLAIN
SELECT
    s.name AS student_name,
    c.name AS course_name,
    sc.score AS exam_score
FROM student s
INNER JOIN score sc ON s.id = sc.student_id
INNER JOIN course c ON sc.course_id = c.id;
```

EXPLAIN里我现在重点看这几个字段：

| 字段 | 说明 |
| --- | --- |
| type | 访问类型，ALL通常表示全表扫描，ref、range一般比ALL好 |
| possible_keys | 可能用到的索引 |
| key | 实际使用的索引 |
| rows | MySQL预估要扫描的行数 |
| Extra | 额外信息，比如Using index、Using where、Using filesort |

```sql
-- 如果name没有索引，可能会全表扫描
EXPLAIN SELECT * FROM student WHERE name = '张三';

-- 建立索引后，再观察key和rows的变化
CREATE INDEX idx_student_name ON student(name);
EXPLAIN SELECT * FROM student WHERE name = '张三';
```

# 总结

这次系统整理MySQL基础增删改查之后，我最大的感受是：SQL真的是后端开发的基本功。以前写JDBC时，我只关心Java代码能不能跑通，现在才发现SQL本身才是和数据库沟通的核心。

我需要牢记的几个点：

1. **理解SQL执行顺序**：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY。只有知道SQL先做什么、后做什么，才能写出正确的分组查询。
2. **DELETE和TRUNCATE不能混用**：DELETE适合按条件删除，也更容易配合事务；TRUNCATE适合清空整张表，但风险更高。
3. **JOIN要先想清楚主表和关系**：INNER JOIN看匹配，LEFT JOIN保留左表，RIGHT JOIN保留右表。
4. **索引要合理使用**：索引应该建在区分度高、经常查询、经常关联的列上，不是越多越好。
5. **用EXPLAIN验证SQL**：查询慢的时候，不要靠猜，要看执行计划。

2018年10月的这个阶段，我觉得自己终于从“会照着写SQL”，开始慢慢变成“知道为什么这样写SQL”了。下一步准备继续学习事务、锁和隔离级别，这些应该会更接近真实项目里的数据库问题。
