去年我还在跟人争论"AI 写的代码能不能用"，今年我已经在用它写完三四个小工具了。这篇不是给大佬的，是给那个**只会写 Hello World、或者在某个自学的晚上刷到无数教程却没动过手**的你。

我把从 0 到 1 的全部过程拆给你看，包括我踩过的坑，和那些没人会告诉你的、关于"AI 替你写代码"的真相。

<!-- more -->

## 先说人话：Vibe Coding 到底是什么

一句话：**你用嘴描述想法，AI 帮你写代码，你在旁边看着它改，直到能用。**

2016 年我学编程的时候，是照着书一行行敲、一行行背。现在你想做一个东西，直接跟 AI 说需求就行，它生成一段代码，你复制粘贴、运行、看看对不对。

听起来像魔法？确实是，但别高兴太早——**魔法是你和 AI 一起变出来的，不是 AI 单方面表演**。

## 第一个小时：装好环境，别急着写代码

我先花 15 分钟把战场清干净，这几样缺一不可：

| 工具 | 干嘛用的 | 装哪 |
| --- | --- | --- |
| **Node.js 20 LTS** | 跑 JavaScript/TypeScript 项目 | [nodejs.org](https://nodejs.org/) |
| **VSCode** | 写代码的编辑器 | [code.visualstudio.com](https://code.visualstudio.com/) |
| **Git** | 存代码 + 后悔药 | git-scm.com |
| **AI 助手插件** | 对话生成代码 | 推荐 GitHub Copilot 或 Cursor |

装完先验证一下环境跑得通，再开脚本域——**别跳过这步**：

```bash
# Windows / Mac / Linux 都行，结果必须是三行版本号
node -v
npm -v
git --version
```

我第一次到最后一步才想起 Git 没装，结果代码全在编辑器里没版本控制，改坏了只能干瞪眼。**环境问题永远比代码问题恶心，先解决它。**

## 第一个项目：让它帮我写个"记账本"

我不空想大项目，第一个就做个小工具——**一个在终端跑的记账本**。这个选择很关键：范围小、能运行见效、随时能丢。

我跟 AI 的第一句话是：

```text
帮我写一个命令行记账本，用 Node.js。
功能：
1. 能加一条收入或支出（金额 + 备注）
2. 能查总余额
3. 数据存到本地文件，退出程序不丢
先跑通最基础功能，别做花里胡哨的。
```

注意最后那句"**别做花里胡哨的**"——这是我最痛的教训。不说这句，AI 会给你加什么图表、导出 CSV、多用户，全是你不想要的东西。

## 它写完了，然后呢？—— 灵魂三问

AI 啪地贴出一段代码 + 一个 `npm install` 命令。这时候新手最容易犯的错：**复制、粘贴、跑、看它成功就完事**。

我给每条 AI 代码都做三件事，一次没落：

### 1️⃣ 它改了我的哪些文件？

```bash
git status
```

这是我睁眼第一件事。AI 有时会"顺手"改一堆跟需求无关的文件——**它很爱干这个**。我看到只加了 `index.js` 和一个依赖，心里有底。

### 2️⃣ 数据从哪来、到哪去？

我不看每一行（那是大佬的事），但我至少要懂**数据流**：

- 记账数据存到了哪个文件？`~/记录.json`？还是当前目录？
- 如果我换个目录跑，还能读到昨天的账吗？

这里我在代码里找到了那行 `fs.writeFileSync('./ledger.json')`——注意那个 `./`，意味着数据存在**当前目录**。我明白这个了，以后换目录就知道数据会丢。

### 3️⃣ 跑坏了怎么滚回去？

```bash
git add index.js
git commit -m "记账本初版"
```

每次改动**先提交**，这是最重要的后悔药。AI 生成代码你不可能完全看懂，但你能保证：**每一版都留了底，改坏了可以回退**。

我第一次写完就急着跑，没 commit。结果 AI 后面改崩了，我恢复不了，只能从头再来一遍。血泪教训。

## 真正的重点：AI 写的代码，谁是负责人？

我必须在这个教程里反复强调这件事，连写三遍都不嫌多：

> **AI 不会参加故障复盘，也不会在凌晨两点判断要不要回滚。**

代码是被你合进去的，commit 写的是你的名字。出了事，是**你**负责，不是 ChatGPT。

所以我的原则很简单，就一条：

| 场景 | 我做什么 |
| --- | --- |
| 记个账、跑一次性的脚本 | 快速用，出了问题重来就行 |
| 碰支付、权限、删数据、生产服务器 | **必须手动确认 + 测试 + 保留回滚** |

**删数据、碰生产环境这两件事，我永远不让 AI 自动执行**，哪怕它信誓旦旦说"没问题"。这不是信不信它——这是软件本来就是"数据、资金、隐私、团队维护成本"叠加的东西，AI 替你省了写代码的时间，省不掉后果。

## 新手最容易翻车的三个坑

### ❌ 坑 1：把需求写得太模糊，然后怪 AI 不行

```text
帮我做个网站。        ← 我最初的真实需求，现在看着都脸红
```

AI 不是神仙，模糊需求只会放大回模糊代码。改进后：

```text
做一个单页记账网站，用 React。
页面左边是输入框（金额 + 说明），右边显示余额。
数据放浏览器 localStorage，不做后端。
先做能跑的最小版。
```

**需求越具体，AI 越靠谱。** 这不是玄学，是上下文质量。

### ❌ 坑 2：让它"一键搞定所有功能"

一次让 AI 做整个系统，就像让一个人同时搬一百个箱子——它一定会摔。

正确姿势是**拆成小步**：

```text
第 1 步：先把"加一条支出"跑通。
第 2 步：再加"查余额"。
第 3 步：最后加"删除记录"。
```

每一步都验证、都 commit。**大项目也是小步骤堆出来的。**

### ❌ 坑 3：把"能跑"当成"做完了"

页面能打开、点得通，**不等于**功能可靠。真实故障都藏在那些你没想到的角落：重复点击、空数据、网络超时、权限绕过。

我后来发现记账本有个 bug：**如果直接按两次回车，会加两条相同的记录**。页面看起来一切正常，但账算错了。这种问题，AI 生成的代码不会提醒你，只能靠你多测多想。

## 两周后，我会走到哪？

我给个诚实的时间线（我自己的真实节奏）：

| 时间 | 你大概能做什么 |
| --- | --- |
| 第 1 天 | 跑通记账本、理解数据流向、学会 commit |
| 第 3 天 | 做第二个小工具，开始自己提"更具体"的需求 |
| 第 1 周 | 敢做一个有 5 个功能的小应用，学会拆步骤 |
| 第 2 周 | 开始懂"哪种代码要小心"（权限、删数据、生产） |

**第 2 周不是你变强了，是你变懂事了**——知道哪些能让 AI 干，哪些得自己盯着。

## 最后一句

Vibe Coding 降低的不是编程的门槛，而是**"想法到能跑的 Demo"的距离**。它让每个人都能把脑子里的东西变成屏幕上能跑的东西。

但记住那句话：**谁提交，谁负责。** AI 帮你写代码，你负责它写得对不对、安不安全、能不能滚回去。

工具会变，责任不会。希望你第二个星期，能敢用 AI 做出一个真正属于你的小东西。
