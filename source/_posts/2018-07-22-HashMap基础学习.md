# 背景

2018 年 7 月，最近把 `List` 相关的内容过了一遍，接下来开始学习 `Map`。和 `List` 按顺序存储元素不同，`Map` 更像是一张“键值对表”，通过 `key` 可以快速找到对应的 `value`。

在 Java 集合框架里，`HashMap` 应该是工作中最常用的数据结构之一。比如根据用户 id 查用户信息、根据配置名查配置值、统计某个字段出现次数等，都很容易想到用 `HashMap`。

![HashMap桶数组与链表结构](/images/posts/2018/2018-07-22-HashMap基础学习-image-1.svg)

刚开始看 `HashMap` 的时候，我觉得它只是“根据 key 存取 value”的工具类。但继续往下学才发现，里面涉及哈希算法、数组、链表、扩容、线程安全、`hashCode` 和 `equals` 等一系列知识点。也难怪它经常出现在面试题里。

# 问题

学习过程中，我主要遇到了下面几个疑问：

1. `key` 为 `null` 时，`HashMap` 到底怎么处理？
2. 以前听说 `HashMap` 不是线程安全的，实际会出什么问题？
3. 如果两个不同的 `key` 算出来的 `hashCode` 一样，数据会不会被覆盖？
4. 遍历 `HashMap` 的方式太多，到底该用哪一种？
5. `HashMap` 和 `Hashtable` 有什么区别？

这些问题如果只停留在“会用 API”的层面，其实很容易混淆。所以我打算先从常用操作入手，再慢慢分析它的底层原理。

# 分析

## 1. HashMap 可以存 null 吗？

`HashMap` 允许一个 `null key`，也允许多个 `null value`。

```java
Map<String, String> map = new HashMap<String, String>();
map.put(null, "空key");
map.put("name", null);
map.put("address", null);

System.out.println(map.get(null));
```

需要注意的是，`key` 是唯一的，所以 `null key` 只能有一个。如果重复放入 `null key`，后面的值会覆盖前面的值。

```java
Map<String, String> map = new HashMap<String, String>();
map.put(null, "第一次放入");
map.put(null, "第二次放入");

System.out.println(map.get(null));
```

输出结果是：

```text
第二次放入
```

## 2. HashMap 为什么不是线程安全的？

`HashMap` 的大多数操作都没有加锁。如果多个线程同时修改同一个 `HashMap`，就可能出现问题。

在 JDK7 中，`HashMap` 扩容时采用头插法迁移链表节点，在并发 `put` 的情况下，链表可能形成环，最终导致查询时死循环。

在 JDK8 中，虽然扩容迁移逻辑有所调整，降低了死循环风险，但 `HashMap` 依然不是线程安全的。多个线程同时 `put` 时，仍然可能出现数据覆盖、数据丢失、扩容状态不一致等问题。

所以结论很明确：如果是多线程写入场景，不要直接使用普通 `HashMap`。

## 3. hashCode 相同怎么办？

`HashMap` 根据 key 的哈希值计算数组下标。不同的 key 可能被计算到同一个数组位置，这种情况叫哈希冲突。

JDK7 中，哈希冲突主要通过“数组 + 链表”解决：多个元素落到同一个桶时，会挂在同一条链表上。

JDK8 中，底层结构变成“数组 + 链表 + 红黑树”。当链表长度达到一定阈值，并且数组容量也达到要求后，链表会转成红黑树，减少极端情况下的查询时间。

![HashMap哈希冲突处理](/images/posts/2018/2018-07-22-HashMap基础学习-image-2.svg)

因此，两个 key 的 `hashCode` 相同，并不代表一定会互相覆盖。`HashMap` 还会继续通过 `equals` 判断 key 是否真正相等。

## 4. 遍历方式应该选哪个？

`HashMap` 的遍历方式很多，比如遍历 `keySet`、遍历 `entrySet`、只遍历 value，或者使用 `Iterator`。

日常开发里，如果同时需要 key 和 value，我更推荐使用 `entrySet`。因为 `entrySet` 可以一次拿到 key 和 value，避免通过 key 再执行一次 `get` 查询。

## 5. HashMap 和 Hashtable 区别

`Hashtable` 是比较早期的集合类，`HashMap` 是后来集合框架中的常用实现。两者主要区别如下：

| 对比项 | HashMap | Hashtable |
| --- | --- | --- |
| 线程安全 | 非线程安全 | 方法使用 synchronized，线程安全 |
| null 支持 | 允许一个 null key 和多个 null value | 不允许 null key 和 null value |
| 性能 | 单线程下通常更好 | 加锁开销较大 |
| 推荐程度 | 日常开发常用 | 现在较少使用 |
| 替代方案 | 多线程场景用 ConcurrentHashMap | 通常不推荐新代码使用 |

# 解决方案

## 1. HashMap 基本 CRUD 操作

先从最基础的增删改查开始。这里我用 `String` 作为 key，`Integer` 作为 value，模拟记录学生成绩。

```java
Map<String, Integer> scoreMap = new HashMap<String, Integer>();

scoreMap.put("张三", 90);
scoreMap.put("李四", 85);
scoreMap.put("王五", 92);

Integer zhangSanScore = scoreMap.get("张三");
System.out.println("张三成绩：" + zhangSanScore);
```

修改和删除也很简单：

```java
scoreMap.put("李四", 88);
scoreMap.remove("王五");

if (scoreMap.containsKey("李四")) {
    System.out.println("李四成绩：" + scoreMap.get("李四"));
}
```

常见判断操作：

```java
boolean hasZhangSan = scoreMap.containsKey("张三");
boolean hasFullScore = scoreMap.containsValue(100);
int size = scoreMap.size();
boolean empty = scoreMap.isEmpty();

System.out.println(hasZhangSan + ", " + hasFullScore);
System.out.println("数量：" + size + ", 是否为空：" + empty);
```

## 2. 用 Student 作为 key 时重写 hashCode 和 equals

如果自定义对象要作为 `HashMap` 的 key，必须特别注意 `hashCode` 和 `equals`。

比如下面这个 `Student` 类，我认为只要 `id` 相同，就是同一个学生。

```java
public class Student {
    private Integer id;
    private String name;

    public Student(Integer id, String name) {
        this.id = id;
        this.name = name;
    }
}
```

这时应该重写 `equals`：

```java
@Override
public boolean equals(Object obj) {
    if (this == obj) {
        return true;
    }
    if (!(obj instanceof Student)) {
        return false;
    }
    Student other = (Student) obj;
    return id != null ? id.equals(other.id) : other.id == null;
}
```

同时必须重写 `hashCode`：

```java
@Override
public int hashCode() {
    return id != null ? id.hashCode() : 0;
}
```

完整使用示例：

```java
Map<Student, String> studentMap = new HashMap<Student, String>();

Student s1 = new Student(1, "张三");
Student s2 = new Student(1, "张三同学");

studentMap.put(s1, "第一次放入");
studentMap.put(s2, "第二次放入");

System.out.println(studentMap.size());
```

如果 `equals` 和 `hashCode` 都按 `id` 判断，那么 `s1` 和 `s2` 会被认为是同一个 key，最后 `size` 是 `1`。

这里最重要的规则是：重写 `equals` 必须重写 `hashCode`。否则两个对象即使 `equals` 返回 `true`，也可能因为哈希值不同而被放到不同桶里，导致 `HashMap` 行为异常。

## 3. HashMap 的 4 种遍历方式

### 方式一：遍历 keySet，再通过 key 获取 value

```java
for (String key : scoreMap.keySet()) {
    Integer value = scoreMap.get(key);
    System.out.println(key + " = " + value);
}
```

这种写法直观，但如果同时需要 key 和 value，会多一次 `get` 查询，不是最推荐的方式。

### 方式二：遍历 entrySet

```java
for (Map.Entry<String, Integer> entry : scoreMap.entrySet()) {
    String key = entry.getKey();
    Integer value = entry.getValue();
    System.out.println(key + " = " + value);
}
```

这种方式性能更好，也更适合需要同时访问 key 和 value 的场景。

### 方式三：只遍历 values

```java
for (Integer value : scoreMap.values()) {
    System.out.println("成绩：" + value);
}
```

如果只关心 value，不关心 key，这种方式最直接。

### 方式四：使用 Iterator 遍历

```java
Iterator<Map.Entry<String, Integer>> iterator = scoreMap.entrySet().iterator();
while (iterator.hasNext()) {
    Map.Entry<String, Integer> entry = iterator.next();
    System.out.println(entry.getKey() + " = " + entry.getValue());
}
```

如果遍历过程中需要删除元素，推荐使用 `Iterator` 的 `remove` 方法，避免 `ConcurrentModificationException`。

```java
Iterator<Map.Entry<String, Integer>> iterator = scoreMap.entrySet().iterator();
while (iterator.hasNext()) {
    Map.Entry<String, Integer> entry = iterator.next();
    if (entry.getValue() < 60) {
        iterator.remove();
    }
}
```

简单对比一下：

| 遍历方式 | 适用场景 | 推荐程度 |
| --- | --- | --- |
| keySet + get | 只想看 key，或代码很简单 | 一般 |
| entrySet | 同时需要 key 和 value | 推荐 |
| values | 只需要 value | 推荐 |
| Iterator | 遍历时需要删除元素 | 推荐 |

## 4. 初始容量和负载因子怎么设置？

`HashMap` 有两个很重要的参数：初始容量和负载因子。

默认情况下，初始容量是 `16`，负载因子是 `0.75`。当元素数量超过 `容量 * 负载因子` 时，`HashMap` 会触发扩容。

如果提前知道大概要存多少数据，可以合理设置初始容量，减少扩容次数。

```java
int expectedSize = 1000;
float loadFactor = 0.75f;
int initialCapacity = (int) (expectedSize / loadFactor) + 1;

Map<String, String> map = new HashMap<String, String>(initialCapacity);
System.out.println("初始容量建议值：" + initialCapacity);
```

不过，`HashMap` 内部容量会调整为 2 的幂。实际开发里可以用一个简单方法计算建议容量：

```java
private static int calculateHashMapCapacity(int expectedSize) {
    if (expectedSize < 0) {
        throw new IllegalArgumentException("expectedSize不能小于0");
    }
    return (int) (expectedSize / 0.75f) + 1;
}
```

使用示例：

```java
int capacity = calculateHashMapCapacity(500);
Map<Integer, String> userMap = new HashMap<Integer, String>(capacity);

userMap.put(1, "用户A");
userMap.put(2, "用户B");
```

这里的思路不是追求绝对精确，而是尽量避免明知道要放很多数据，却还使用默认容量导致频繁扩容。

## 5. 多线程场景使用 ConcurrentHashMap

如果多个线程会同时读写 Map，可以考虑使用 `ConcurrentHashMap`。

```java
Map<String, Integer> countMap = new ConcurrentHashMap<String, Integer>();

countMap.put("Java", 1);
countMap.put("HashMap", 2);

Integer count = countMap.get("Java");
System.out.println("Java出现次数：" + count);
```

需要注意的是，`ConcurrentHashMap` 不是简单地给所有方法都加一把大锁。它内部做了更细粒度的并发控制，所以在并发场景下通常比 `Hashtable` 更合适。

不过，复合操作仍然要小心。例如“先判断再放入”不是天然原子的，可以优先使用 `putIfAbsent`。

```java
ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<String, Integer>();

Integer oldValue = map.putIfAbsent("Java", 1);
if (oldValue == null) {
    System.out.println("第一次放入Java");
}
```

# 总结

这次学习 `HashMap`，我最大的感受是：它看起来简单，但底层并不简单。

`HashMap` 是面试高频题，也是实际开发中非常常用的集合类。只会 `put` 和 `get` 当然可以完成很多需求，但如果不了解底层原理，就容易在哈希冲突、扩容、线程安全、自定义 key 等问题上踩坑。

我给自己总结了几条使用原则：

1. `HashMap` 允许一个 `null key` 和多个 `null value`。
2. 两个 key 的 `hashCode` 相同不会直接覆盖，还要继续比较 `equals`。
3. 同时需要 key 和 value 时，优先使用 `entrySet` 遍历。
4. 能预估数据量时，可以设置合适的初始容量，减少扩容。
5. 多线程写入场景不要直接使用 `HashMap`，可以考虑 `ConcurrentHashMap`。
6. 自定义对象作为 key 时，重写 `equals` 必须重写 `hashCode`。

学完这些内容后，我再看 `HashMap` 就不只是一个“键值对容器”了，而是能联想到数组、链表、红黑树、哈希冲突和并发安全等知识点。理解底层原理，才能真正把这个常用工具用好。
