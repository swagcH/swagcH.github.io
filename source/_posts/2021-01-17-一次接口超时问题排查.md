# 背景

接口超时的排查重点是确认耗时发生在入口、数据库、缓存还是下游服务。

```text
记录类型：故障排查
记录年份：2021

```

# 问题

```text
2021-01-17 20:18:42 WARN  order-api request timeout
path=/api/orders/submit
cost=8123ms
traceId=adf9c0a2b1
upstream=payment-service
```

```bash
curl -w "dns:%{time_namelookup} connect:%{time_connect} start:%{time_starttransfer} total:%{time_total}
"   -o /dev/null -s http://localhost:8080/api/orders/submit
```

# 分析

```bash
grep "adf9c0a2b1" app.log
cat app.log | grep "payment-service" | tail -100
jstack $(pgrep java) > /tmp/order-api.jstack
```

```text
排查顺序：
1. 确认是单接口还是全站超时
2. 对比接口入口耗时和下游调用耗时
3. 查看线程是否阻塞在外部 HTTP 调用
4. 检查连接池、超时参数、重试次数
```

# 解决方案

```yaml
payment:
  connect-timeout-ms: 1000
  read-timeout-ms: 2000
  max-retry: 1
```

```java
RequestConfig config = RequestConfig.custom()
    .setConnectTimeout(1000)
    .setSocketTimeout(2000)
    .setConnectionRequestTimeout(500)
    .build();
```

# 总结

```text
复盘要点：
1. 先保留现场，再尝试恢复
2. 先确认影响范围，再判断根因
3. 日志、监控、配置、代码需要串起来看
4. 修复动作必须可验证
5. 故障结束后补充检查项和自动化规则
```
