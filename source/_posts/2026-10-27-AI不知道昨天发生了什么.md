十月下旬有一条新闻，标题看着不太"AI"：**OpenAI 宣布不再使用实时互联网数据训练前沿模型**，理由是这样存在"显著风险"。

这个决定听起来有点反直觉。大部分人默认的逻辑是：AI 越用越聪明，互联网上的新东西它应该随时都在学。

但事实正好相反。**大模型的知识是"冻结"的**，它不知道昨天发生了什么。这篇文章讲清三件事：知识为什么会被冻结、想让它知道新东西只有哪几条路、以及每条路的代价。

## 一、先理解一件事：模型不是在学习，是在预测

要理解"知识截止"，得先看模型到底在做什么。

你问它一个问题，它不是去数据库里查一段标准答案，而是在**已有的上下文后面，持续预测下一个最可能出现的 token**。这些 token 连起来，才看起来像一段回答。

那"知识"是怎么进去的？靠**预训练**：一次性喂给它海量文本，让它在这个过程中把语言规律和事实关联"压缩"进参数里。

关键在于——**这个过程是一次性的**。

训练完成，参数就固定了。此后你每次调用，用的都是同一批参数。它不会因为你今天问了一个新问题，就更新自己的知识。

所以你会在各种模型文档里看到一个字段：**知识截止日期**（knowledge cutoff）。

```
GPT-4 系列  ≈ 2023 年底
Claude 系列 ≈ 2024 年中
各种开源模型 ≈ 训练数据停止采集的那天
```

这也解释了一个日常困惑：

> "明明是 2026 年了，为什么它还会推荐一个已经废弃的库版本？"

因为它"记得"的是训练数据里的那个世界。**不是它偷懒，是它真的不知道。**

## 二、想让模型知道新东西，只有三条路

从技术上来说，不存在第四种。区别只在成本和可控性。

![模型知识的三条来源与代价对比](/images/posts/2026/ai-knowledge-three-paths.svg)

### 路线一：重新预训练

把新数据混进去，再跑一遍（或继续跑一部分）训练。

**代价**：

- **钱**。前沿模型的预训练成本在千万美元量级，中小团队根本碰不了。
- **时间**。从数据清洗到训练完成，周期以月计。
- **数据质量风险**。这条最关键——如果新数据里混进了错误内容，模型会把错误学进参数。而且**参数是个黑盒**，你没法定位"哪一条数据导致了哪个错误回答"。

这也是为什么 OpenAI 这次干脆停掉"实时互联网训练"。**互联网上的内容良莠不齐，还混着大量模型自己生成的内容**。把模型生成的内容再喂回去训练，长期会让模型越来越退化——业内管这叫**模型崩塌**（model collapse）。

### 路线二：RAG（检索增强生成）

不动模型参数，把资料放在外面。回答前先去检索，把命中的片段塞进上下文，让模型"看着资料回答问题"。

**代价**：

- **依赖检索质量**。检索没找对，模型就只能靠猜或者拒答。检索这块做不好，RAG 的效果会比直接问还差——因为错误资料比没有资料更危险。
- **要维护资料管线**。文档怎么切分、怎么更新、怎么处理版本，都是持续成本。
- **受上下文长度限制**。塞进去的片段越多，成本和延迟越高。

**但它有一个别人给不了的好处：可溯源。**

检索命中的是原文片段，你可以告诉用户"这句话来自《XX 制度》第 3.2 节"。这在企业内部场景里几乎是刚需——**答案对不对可以复核，责任可以追溯**。

### 路线三：联网搜索

让模型自己调搜索工具，实时查。

**代价**：

- **不可控**。搜到什么用什么，质量取决于搜索引擎和模型怎么理解搜索结果。
- **不可溯源**（或者溯源很弱）。你能看到它引用了哪个链接，但没法保证说的就是那个链接里的意思。
- **慢，而且贵**。多一次外部调用，延迟和成本都上去了。

### 三条路的对比

| | 重新预训练 | RAG 检索 | 联网搜索 |
|---|---|---|---|
| **知识更新** | 慢（月级）| 快（改资料即可）| 实时 |
| **成本** | 极高 | 中 | 低（但有外部依赖）|
| **可溯源** | ❌ 黑盒 | ✅ 能指到原文 | ⚠️ 弱 |
| **可控性** | 低 | 高 | 低 |
| **适合场景** | 通用能力提升 | 企业知识库、制度问答 | 时效性资讯 |

## 三、RAG 还是微调：企业知识库怎么选

这是我在做 AI 门户方案时被问最多的一个问题，也是面试里的高频题。

先澄清一个常见误解：**微调和 RAG 不是同一层面的东西**。

- **微调**改的是"模型的行为方式"——语气、格式、特定任务的输出结构。
- **RAG** 改的是"模型能看到什么"——事实和资料。

所以决策其实很简单：

![RAG 与微调的选型决策](/images/posts/2026/rag-vs-finetune.svg)

```
要解决的是"它不知道我们公司的事"      → RAG
要解决的是"它说话不像我们的客服"      → 微调
要解决的是"它老是引用过期的制度"      → RAG + 资料版本管理
要解决的是"它输出格式老是不对"        → 微调（或干脆用结构化输出约束）
```

**绝大多数企业知识库场景，答案是 RAG。** 原因很实在：

1. **资料会变**。制度改了、产品线调整了，改索引就行，不用重训。
2. **需要溯源**。微调学到的东西说不清出处。
3. **成本**。微调一次几万到几十万，RAG 是持续的运维成本，可以从小做起。

只有在"行为"层面确实需要调整、而且数据量足够时，微调才划算。

## 四、我踩过的一个坑

去年我把自建模型网关接进几个项目之后，遇到一个反复出现的现象：

同事问"这个 SDK 最新版本怎么初始化"，模型给的是一年前的写法。仓库里的代码跟着写，跑起来报错。

第一反应是"模型不行"。但换个角度想——**它没错，它只是不知道**。那个 API 是它训练完之后才改的。

后来我们做了两件事：

1. **在网关层统一注入当前日期和"知识可能过时"的提示**，让它遇到不确定的 API 时倾向于说"建议查官方文档"而不是硬编一个版本号。
2. **把内部文档做成检索层**，涉及项目约定的问题走检索，不靠模型记忆。

这两件事都不复杂，但效果比换一个更强模型明显得多。因为**问题的根子不在模型能力，在知识边界**。

## 五、结论

回到开头那条新闻。OpenAI 停止用实时互联网训练，表面看是"AI 变笨了"，实际上是在承认一个工程现实：

> **模型的知识是有边界的，而这个边界不该靠"喂更多实时数据"来突破。**

对做应用的工程师来说，这件事的实际意义是：

1. **别指望模型知道最新的事**。涉及版本、政策、内部制度的，必须有外部知识源。
2. **知识更新是应用层的事，不是模型层的事**。这也是为什么 RAG 会成为过去两年最实在的 AI 工程实践——它把"更新知识"这个动作，从几千万美元的训练，降到了"改一个文档索引"。
3. **可溯源比更聪明重要**。在企业场景里，一个能指出出处的普通回答，比一个正确但说不清依据的精彩回答有价值。
