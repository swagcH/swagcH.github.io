2018年度学习总结

发表于 2018-12-30 更新于 2026-08-26 分类于 随笔 阅读次数：

现在是 2018 年 12 月 30 日深夜，窗外很安静，桌面上摊着几本书、一杯凉掉的咖啡、开着 IDE 的屏幕。刚刚跑通了一个 Spring 的小 Demo，不算什么了不起的东西，但我盯着控制台里那几行日志，愣是坐了好一会儿。

总觉得该写点什么，为这一年。

回头看，2018 年是我真正踏进编程世界的第一年。从连编辑器都不会配，到能用 Java 写点能跑的东西，这三百多天走得七拐八拐，中间有好几次差点放弃。趁着跨年前这个安静的夜晚，把这一年的路好好捋一捋。

背景

2018 年 1 月，我坐在电脑前打开了一本 C 语言的电子书，那是我和编程的第一次正式见面。

在此之前，我对编程的全部认知大概就是——很酷、很复杂、不适合我。高考报志愿时阴差阳错进了计算机相关专业，大一上学期懵懵懂懂地过了，真正开始认真对待，就是从 2018 年开始的。

最开始学的是 C 语言，指针、内存管理、结构体——说实话，学得挺痛苦的。尤其是指针，绕来绕去，debug 的时候经常对着一个段错误发呆半小时。但也正因为 C 的硬核，让我对内存、对程序的底层运行有了一点感觉。

到了三四月份，我开始纠结一个问题：C 语言当然好，但它适合作为长期深耕的方向吗？当时打听了不少学长，也刷了很多帖子，结论是——Java 在后端领域生态成熟、岗位多、学习路径清晰。于是我做了一个重要的决定：转学 Java。

这个决定，基本定义了我整个 2018 年剩下的路。

问题

目标定下来之后，真正走起来才发现，问题一个接一个。

1. 学习路线不清晰，走了不少弯路

网上关于 Java 学习的资料和路线图很多，但信息多到让人不知道该信谁。今天看到一个博客说先学 Java SE，明天又有人说直接上手 Spring Boot。我是那种喜欢把”所有前置知识”都学完再做事情的人，结果就是在基础语法阶段兜兜转转了太久。

2. 光看不练，眼高手低

这是我这一年最大的毛病。

看书的时候觉得自己都懂了——不就是面向对象吗，不就是集合框架吗，有什么难的。但是合上书，打开 IDE，写一个简单的增删改查都要查半天 API。印象最深的是学完 HashMap 原理之后，自己试着实现一个简化版本，写到一半发现根本不知道从哪里下手。这才意识到，”看懂”和”会写”之间隔着十万行代码的距离。

3. 遇到问题不敢问

当时加了一些技术群，也在论坛上潜水。遇到问题第一反应不是去问，而是反复怀疑自己是不是太笨了——这么基础的东西都不懂。于是经常一个人卡在一个小 bug 上几个小时，浪费大量时间。后来才明白，每个经历过自学的人都是从这些坑里爬出来的，问问题不是丢人的事。

4. 博客看得多，写得少

我的浏览器书签里收藏了上百篇文章，从 HashMap 源码分析到 JVM 内存模型，应有尽有。每天刷好几篇，刷完觉得充实。但一个月后回头看，脑子里能留下的印象很模糊。因为光看不写，知识的留存率太低了。

5. 时间管理不好，经常拖延

“今天太累了，明天再看吧”——这句话几乎是我上半年的口头禅。没有固定的学习时间，没有计划，全凭热情驱动。热情高的时候一天学八个小时，没状态的时候一周都不碰代码。这种节奏非常低效。

分析

后来我慢慢想明白了这些问题的根因，也在下半年做了一些调整。

学习规划的重要性

没有规划的学习就像没有地图的旅行。知识海洋是无限的，但个人的时间和精力是有限的。后来我给自己定了一条原则：选定一个方向，找到一条被验证过的路线，先踏踏实实走完，不要中途反复切换赛道。

编程是手艺活

我越来越理解一个道理：编程像学游泳，你看再多教学视频，不下水就永远学不会。代码必须亲手敲，bug 必须亲自查，项目必须亲手做。任何一个你”觉得”懂了但写不出来的知识点，都说明你还没真正掌握它。

后来我强迫自己每学一个新知识点，就写一段代码验证它，哪怕只是一个十行的小 demo。

社区和交流的价值

下半年我开始尝试在群里发言，偶尔回答一些别人提的问题。我发现教是最好的学——为了回答一个问题，你往往需要把那个知识点重新梳理一遍，这个过程本身就是一次高质量复习。而且当你发现别人也会犯和你一样的错误时，那种”只有我不行”的焦虑感会少很多。

写作是深度学习的加速器

十月份开始写博客之后，我明显感觉到自己对知识的理解深了一层。因为要把一个东西讲清楚，你必须先把它真正搞懂。写作强迫你梳理逻辑、查漏补缺、用自己的语言重新表达。这个过程比单纯地读十篇文章都有效。

固定学习节奏

下半年我开始用番茄工作法，每 25 分钟专注学习，然后休息 5 分钟。同时给自己定了规矩：每天晚上 8 点到 10 点是固定学习时间，雷打不动。效果比”等我有时间了再学”好太多。

解决方案

说是解决方案，其实没有那么多方法论。就是一个普通人在跌跌撞撞中，按季度一步步走过来的真实记录。

Q1（1-3 月）：C 语言入门，决定转 Java

年初从 C 语言开始，把指针、数组、结构体这些基础概念过了一遍。过程中有过一点小小的成就感——当第一个指针程序运行正确的时候，那种感觉确实很奇妙。但也逐渐意识到，C 语言在应用层面的天花板比较低，对我来说更适合作为理解计算机底层的基础，而不是长期主攻方向。

三月份做了全年最重要的决定：转向 Java。

这个决定不是一时冲动。当时花了一周时间调研，看了很多自学路线帖和招聘要求，确认 Java 在服务端开发中的地位和前景。确定了方向之后，整个人的心态反而安定下来了——不再东张西望，就朝这一个方向走。

接着就是搭环境。JDK 安装、环境变量配置、第一个 IDE（Eclipse）的安装和使用。这些现在看来基础得不能再基础的操作，当时每一步都可能卡住。JDK 版本选哪个？环境变量配不对怎么办？Eclipse 为什么打不开？每一个问题都要查好久。

当 Hello World 终于出现在控制台的时候，我截图发了个朋友圈。虽然现在想来有点好笑，但那一刻真的觉得——这个大门，我算是挤进来了。

Q2（4-6 月）：Java 语法基础

第二季度是大量输入基础知识的时候。

从基本数据类型、运算符、流程控制开始，然后是面向对象三大特性——封装、继承、多态。这些东西第一次接触时确实觉得抽象，尤其是多态，学完之后做题会做，但问自己”多态在实际项目中有什么用”就答不上来。后来才明白，有些东西的理解是分阶段的——先记住，然后在使用中慢慢感受。

五月份学到集合框架。ArrayList、LinkedList、HashSet、HashMap——每个实现类都过了一遍，大概理解了接口和实现分离的设计思想。

这三个月基本是靠看书 + 看视频 + 敲 demo 过来的。节奏不算快，但比较扎实。每学完一个章节，就把书上的代码亲手敲一遍，改一改，看输出有什么变化。

Q3（7-9 月）：深入 Java，完成第一个小项目

暑假是全年学习效率最高的一段时间。

七月啃 HashMap。那时候看了好几篇源码分析的文章，自己也把源码拉下来断点跟踪。虽然当时对红黑树的理解还很浅，但至少搞清楚了哈希冲突怎么解决、扩容机制是怎么回事。也在这个月第一次写博客——HashMap 基础学习，写得很浅，但迈出了第一步。

八月学异常处理机制，写了 Java 异常处理机制。然后开始学 JDBC，这是第一次把 Java 和数据库联系起来，写了篇文章 JDBC 连接 MySQL 实践。

九月最重要的事情是完成了第一个完整的 Java 小项目——学生管理系统。

说是系统，其实就是一个控制台程序：从 MySQL 里读取学生数据，展示在控制台上，支持增删改查。技术上没什么难度，但对我来说意义很大——我第一次经历了”从零开始分析需求、设计数据结构、写代码、调试、最终跑通”的完整流程。也正是在这个项目里，我初次感受到了写代码的快感。

Q4（10-12 月）：数据库、Linux、Spring 入门

第四季度开始进一步拓展广度。

MySQL 部分不再满足于基本的 CRUD，开始深入学习表设计、索引、事务隔离级别。也正是在这个过程中，我才理解了为什么三范式、为什么加索引、什么时候用 InnoDB 什么时候用 MyISAM。

十一月开始接触 Linux。装了一个虚拟机，装 CentOS，学着用命令行操作文件、配置网络、装软件。一开始觉得没有图形界面很不习惯，但后来慢慢体会到了命令行的高效。这期间也学会了搭 Nginx 和部署简单项目。

十二月的关键词是 Spring。终于在年底正式接触到了这个如雷贯耳的框架。从 IoC（控制反转）和 DI（依赖注入）的概念开始，慢慢理解为什么 Spring 能让代码变得松耦合。十二月中旬跑通了第一个 Spring 项目，虽然只是配置了几个 Bean，做了最简单的依赖注入，但那种”原来框架是这样工作的”的感觉让我兴奋了好几天。

2019 年计划

坐在 2018 年的尾巴上，对明年有一些想法：

  • 框架学习：把 SSM（Spring + SpringMVC + MyBatis）这个组合啃下来，搭建一个完整的 Web 项目
  • Redis：学习缓存，理解 NoSQL 的适用场景
  • 项目实战：不再满足于 demo 和小工具，至少做一个拿得出手的完整项目
  • 坚持写博客：把学到的东西沉淀下来，不管写得好不好，先写
  • 更多交流：尝试去回答别人提出的问题，在社区中参与讨论

总结

2018 年结束了。

这一年走过的路，用代码来表达大概是这样的：

代码不会骗人。这一年的输入和输出清清楚楚地写在上面。

关于心态的变化可能比知识的增长更重要。年初的时候我总觉得编程是一件需要天赋的事情，那些写框架的人、做开源项目的人，一定天生就比普通人聪明。现在我不这么认为了。我看到的所有”厉害的人”，不过是在你看不到的地方，花了你想象不到的时间。

编程是一种技能，技能是可以靠持续练习获得的。这一年教会我最大的道理就是：不要高估一天能学到的东西，不要低估一年能积累的东西。

当然也有遗憾。有些知识点学得不够深入，很多 bug 挡了一下就绕过去了，没有彻底搞清楚根源。有些计划中的书没看完，有些想写的博客没来得及写。

但没关系。2019 年还会继续。

最后的最后，用一句话总结这个深夜的感慨吧：

这一年，从 Hello World 写到了 Spring 容器；从对着控制台发呆，到享受 Debug 通过那一刻的畅快。路还很长，但至少，我开始享受写代码这件事了。

2019，继续写下去。
