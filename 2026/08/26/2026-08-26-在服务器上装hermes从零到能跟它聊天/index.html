在服务器上装 Hermes：从零到能跟它聊天，我踩了哪些坑

发表于 2026-08-26 分类于 折腾记录 阅读次数：
把 Hermes Agent 装到 Linux 服务器上，配成开机自启，能在飞书里跟它聊天。一篇大白话教程，含我实际踩的坑。

在服务器上装 Hermes：从零到能跟它聊天，我踩了哪些坑

说真的，AI Agent 这东西装在本地电脑上其实挺尴尬的——你总不能把笔记本一直开着，让它 24 小时待命吧。

所以我就想：能不能把它装到我的云服务器上？让它一直跑着，微信/飞书/邮件随时能叫起来干活。

折腾了一晚上，还真搞定了。这篇文章就把我做的每一步都写下来，包括中间踩的坑，给也想这么干的人一个参考。

先说我要达成什么

我想要的是这样：

  • Hermes 跑在云服务器后台，关掉 SSH 它也照常工作
  • 在飞书里发消息能直接调它（不是网页版那种）
  • 服务器重启了不用我手动起来

听起来简单对吧。实际上每一步都有坑。

准备工作：你的服务器得有这些

先看下我用的环境，后面所有命令都是基于这个：

🐧
系统
OpenCloudOS 9.4
CentOS 系
⚙️
架构
x86_64
💚
Node
v22.15.0
🐍
Python
3.11.6

💡 小贴士：Node 版本要 >= 20，我装的是 22，没问题。如果你的系统是 Ubuntu/Debian，绝大部分命令也一样，只有 yum/dnf 换成 apt 的事。

第一步：装 Node.js

这个不是装 Hermes 必须的（它其实有 Python 版本），但官方文档和大部分教程都按 Node 走，而且后面如果你想自己写点工具脚本也会用到。装上不亏。

① 先看看有没有装：

● ● ● ~ terminal
$ node --version

② 没装的话装一下：

● ● ● ~ install 运行中
$ # OpenCloudOS / CentOS
$ dnf install -y nodejs npm
$ # Ubuntu / Debian（如果你的系统是这类）
$ apt install -y nodejs npm

③ 装完验证一下：

● ● ● ~ verify
$ node --version
v22.15.0
$ npm --version
10.9.2

⚠️ 注意：如果版本太低（Node < 20），就别用系统源了，去 Node 官网下 LTS。

第二步：装 Hermes

这是正文。打开 Hermes Agent 的 GitHub，README 写得很清楚。

● ● ● ~ curl install 关键命令
$ curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash

跑完会让你选几个东西。这步我栽过跟头，所以我一个个说。

🟢 第一个选择：装哪里

Install directory [/usr/local/lib/hermes-agent]:

直接回车用默认 /usr/local/lib/hermes-agent 就行。改路径后面配 systemd 会麻烦。

🟡 第二个选择：要不要启 gateway

Start the gateway now? [Y/n]:

选 Y。gateway 就是 Hermes 跟外部世界（飞书、微信）通信的桥梁。不启它就是个命令行工具，不能在飞书里调它。

🔴 第三个选择：要不要开机自启

Enable systemd service? [Y/n]:

选 Y。你不会想每次重启服务器都手动 hermes gateway start 吧。

装完最后会给你一个表格，类似这样：

✅ Installation complete
Install dir:/usr/local/lib/hermes-agent
Python venv:.../venv
Gateway:running
Systemd:enabled

第三步：验证装好了

不管安装脚本怎么说，自己跑一遍命令确认：

● ● ● ~ hermes --version
$ hermes --version
Hermes Agent v0.20.5 (2026.8.19) · upstream 1bbb6e5b
Install directory: /usr/local/lib/hermes-agent
Install method: git

看到版本号就算装好了。

再查下 gateway 是否在跑：

● ● ● ~ systemctl status
● hermes-gateway.service - Hermes Agent Gateway
Loaded: loaded
Active: active (running) since Tue 2026-08-25 23:30:03 CST
Main PID: 1998472 (hermes)
Memory: 596.5M

✅ active (running) 就对了。如果显示 inactive (dead)，手动起一下：

第四步：配飞书（或者你用的 IM）

这一步是真正能聊天的环节。Hermes 支持飞书、Slack、WhatsApp、邮件……我自己用飞书，所以只讲飞书。

4.1 先在飞书开放平台建个应用

打开 飞书开放平台，登录后：

  1. 点「创建企业自建应用」
  2. 名字随便起，比如「我的 Hermes 助手」
  3. 头像、描述随便填
  4. 进应用详情页，记下 App ID 和 App Secret（后面要用）

4.2 配权限

在应用的「权限管理」里，至少要勾这几个：

📋 飞书权限清单
● im:message — 收发消息
● im:message:send_as_bot — 以机器人身份发消息
● im:message.p2p_msg — 私聊（1v1 跟它聊）
● im:message.group_at_msg — 群聊 @ 机器人

申请完要点「发布版本」才生效。

4.3 配事件订阅

在「事件订阅」里：

  • 请求网址 URL：填 https://你的服务器公网IP:端口/hermes/feishu/webhook
    • 注意要先用 nginx 或别的反代把 HTTPS 配上，飞书只接受 HTTPS
    • 或者用 ngrok 这种内网穿透

💡 小贴士：加密策略选「加密」或「明文」都行，新手选明文调试更简单。

4.4 把凭证告诉 Hermes

回到服务器，跑：

● ● ● ~ 配置
$ hermes setup feishu

它会问你 App ID 和 App Secret，照着填。配置文件会写到 ~/.config/hermes/feishu.json，权限 600。

填完重启 gateway：

● ● ● ~ restart
$ systemctl --user restart hermes-gateway.service

4.5 验证

在飞书里找你的机器人发一条「你好」。这里我翻车过一次——消息发过去完全没反应。

排查思路：

🔍 排查三连
1. 看 gateway 日志
journalctl --user -u hermes-gateway -f
2. 看有没有收到回调
grep "feishu" ~/.hermes/logs/*.log
3. 检查端口监听
ss -tlnp | grep hermes

⚠️ 我当时的问题：事件订阅的 URL 没配对。配的是 http://...，飞书非要 https://...。改成反代之后就好了。

第五步：跑个真任务试试

别光发”你好”测试。用任务验证它才是真的。

我让它干的第一件事：

「帮我看下当前服务器都跑了哪些服务，按 CPU 占用排序」

它的回复（精简版）：

🤖 Hermes Agent
跑了 21 个 systemd 服务 + 2 个 Docker 容器。
按 CPU 排：
1. kswapd0 (内核) - 17.2%
2. hermes-gateway (我自己) - 8.7%
3. mysqld - 11.5%
...

OK 它确实在跑、确实能看到系统。装到这里就算完整跑通了。

我踩的坑（建议你提前避）

坑 1：systemd 用错了 user 还是 system

Hermes 装的是 ~/.config/systemd/user/hermes-gateway.service，是用户级的。

所以**所有命令都要加 --user**：

✅ 正确
systemctl --user status hermes-gateway
❌ 错误
systemctl status hermes-gateway
→ 找不到服务

💡 如果你服务器开了多用户，gateway 跟用户绑定。用户退了 gateway 也停。要全局用就改成 system 级，但官方不推荐。

坑 2：Node 版本 < 20 装不上

⚠ ERROR: Hermes Agent requires Node.js 20+ (found 18.17.0)

老老实实装新版。

坑 3：飞书事件订阅 URL 必须 HTTPS

这个上面提了。如果你懒得搞反代，用 ngrok 一行命令解决：

● ● ● ~ ngrok
$ ngrok http 8765

把 ngrok 给你的 https 地址填进飞书就行。仅限测试用，生产环境别这么干。

坑 4：防火墙没开

📋 排查步骤
① 看端口监听
ss -tlnp | grep -E '8765|hermes'
没监听 = gateway 没起来
② 起了但外面连不上 = 防火墙
firewall-cmd --add-port=8765/tcp --permanent
firewall-cmd --reload

⚠️ 云服务器（阿里云/腾讯云）还要去控制台的安全组里开端口，不然白搭。

坑 5：内存不够被 OOM kill

Hermes gateway 启动后内存大概 400-600MB。如果你的服务器只有 1GB 内存，跑它一个就吃满了，再加别的服务就被 OOM。

💡 建议：至少 2GB 内存起步。

日常怎么用

装好之后基本不用管它了。常用命令：

🛠️ 常用命令
# 查 gateway 状态
hermes gateway status
# 看最近日志
hermes logs --tail 50
# 重启 gateway
systemctl --user restart hermes-gateway
# 完全卸载（如果你哪天不想要了）
hermes uninstall

如果你想让它主动做点什么（比如每天早上 7 点给你发新闻），那就要用 hermes cron：

~ hermes cron
hermes cron list       # 列出所有定时任务
hermes cron run <job_id>    # 手动跑一次
hermes cron pause <job_id>   # 暂停
hermes cron resume <job_id>  # 恢复

这个我另一篇文章会写。

最后说两句

装完 Hermes 在服务器上跑了快两周了，最大的感受是：这玩意真的能当个私人助手用。

不是那种”打开网页问一句、答完就走”的玩具，而是真的在你服务器上待命、知道你的环境、能直接动你文件的助手。

比如我最近写代码遇到一个 Node 的报错，直接在飞书里描述给它，它让我贴 log、让我跑几条命令诊断，最后定位到是某个 npm 包的版本冲突——整个过程我手都没离开手机。

当然它不是万能的。复杂决策、需要物理操作的事它干不了。但作为一个 7x24 待命的程序，它比大部分同类都靠谱。

如果你们也想装，按我上面写的顺序走一遍，应该 1-2 小时搞定。中间卡住了欢迎来问我——别一个人闷头搞，那是最慢的方式。
