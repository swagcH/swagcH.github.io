从 0 到 1 的 Vibe Coding 教程：当 AI 开始替我写代码

发表于 2026-09-12 更新于 2026-10-09 分类于 AI编程 阅读次数：

去年我还在跟同事争”AI 写的代码能不能上生产”，今年我已经用它攒了三四个小工具，其中一个还真跑在我自己的服务器上。

这篇不是给架构师的，是给只会写 Hello World、或者刷了一堆教程但没真动过手的你。我把从 0 到 1 的全过程摊开讲，包括踩的坑，以及那些讲 AI 编程的文章通常不会提的事。

一句话说清 Vibe Coding 是什么

你用大白话描述需求，AI 把代码写出来，你在旁边盯着它改，直到真能用。

2016 年我学编程，是照着书一行行敲、一行行背。现在你想做点东西，直接说需求就行。

听着很爽，但别急着高兴。更准确的说法是：你多了个手速极快、记性极好、但不懂你的业务、也绝不替你担责的实习生。它产出的东西，一律要过你这一关。

术语上讲，它是个高吞吐、低置信度的代码生成器 —— 吞吐高所以省时间，置信度低所以必须 review。这两句话你得同时记住，只记前半句就是灾难的开始。

第一个小时：先把环境弄干净，别急着写代码

我先花 15 分钟清战场。这几样缺一个都难受：

工具 干什么的 去哪装
Node.js 20 LTS 跑 JavaScript / TypeScript 项目 nodejs.org
VSCode 写代码的编辑器 code.visualstudio.com
Git 版本控制，也就是后悔药 git-scm.com
AI 助手 对话生成代码 GitHub Copilot 或 Cursor 都行

我第一次就是嫌麻烦没验 Git，等到最后才发现没装。结果代码全躺在编辑器里没有版本控制，改崩了只能干瞪眼。

顺带说一个后面会反复用到的概念：依赖要锁版本。项目里那个 package-lock.json 别删，别人（以及半年后的你）靠它才能装出跟你一模一样的环境。团队协作里，npm ci 比 npm install 靠谱 —— 前者严格照 lock 文件装，后者可能悄悄给你升级。

代码到手，先问三件事

AI 啪地贴出一段代码，外加一个 npm install。新手最容易犯的错就在这：复制、粘贴、跑、看到没报错就收工。

我每条 AI 代码都过这三关，一次没落下。

第一件：它动了哪些文件？

git status 看改动面，git diff 看具体改了哪几行。AI 有时会”顺手”改一堆跟你需求无关的文件，它很爱干这个。我那次看到只多了 index.js 和一个依赖声明，心里就有底了。

这一步的专业叫法就是 diff review。你不用逐行读懂（那是资深工程师的活），但必须知道改动落在哪几个文件、动了什么类型的东西。

第二件：数据从哪来、到哪去？

我不逐行看代码，但一定搞清楚数据流：

  • 账记到哪个文件了？~/ledger.json？还是当前目录？
  • 我换个目录再跑，还读得到昨天的账吗？

第三件：跑坏了怎么滚回去？

每完成一小步就提交，这是最重要的后悔药。AI 写的代码你不可能全看懂，但你能保证每一版都留了回滚点。

我第一次写完就急着跑，没提交。后来 AI 改崩了，我回不去，只能从头再来。从那以后我定了个规矩：一个可验证的功能 = 一次提交。别攒一大堆改动一起提交，那样回滚点也是模糊的。

责任这件事，没有灰色地带

这句话我在这篇里要说三遍：

AI 不会参加故障复盘，也不会在凌晨两点判断要不要回滚。

代码是你合进去的，commit 上写的是你的名字。出事的时候，是你的问题，不是 ChatGPT 的。

所以我的原则只有一条，按风险分档：

场景 我的做法
记个账、跑一次性脚本、本地小工具 快速用，坏了重来就是
碰支付、权限、删数据、生产服务器 手动确认 + 测试 + 留回滚预案，一样不能少

删数据和碰生产这两件事，我永远不让 AI 自动执行，哪怕它信誓旦旦说”没问题”。这不是信不信它的问题 —— 软件本来就是”数据 + 资金 + 隐私 + 团队维护成本”叠出来的东西，AI 省掉的是你敲代码的时间，省不掉后果。

顺便提一个很实用的词：幂等。同一个操作重复执行，结果应该一致。这个坑我在下一节就踩到了。

新手最容易翻车的三个坑

坑 1：需求写得太模糊，然后怪 AI 不行

需求越具体，AI 越靠谱。 这不是玄学，是上下文质量 —— 你给它的约束越硬，它自由发挥（也就是跑偏）的空间越小。

坑 2：想让它”一键搞定所有功能”

一次让 AI 写完整个系统，就像让一个人同时搬一百个箱子，必然摔。

正确姿势是拆成垂直切片：每一步都是一个”从界面到数据”能跑通的小功能，而不是”先写完全部后端再写前端”。

每一步都验证、都提交。大项目也是小步骤堆出来的，区别只在于步骤数量。

坑 3：把”能跑”当成”做完了”

页面能打开、按钮点得通，不等于功能可靠。真实故障都藏在你没想到的角落：重复点击、空数据、网络超时、权限绕过。

我的记账本就有一个：连按两次回车，会记两笔一模一样的账。界面看着一切正常，账却是错的。这就是典型的幂等缺失 —— 重复提交没有被拦住。

这类问题 AI 不会主动提醒你，只能靠你多测两下、多想一步。边界条件才是故障高发区，正常路径反而是最不容易出事的。

两周之后，你大概在哪

不画大饼，这是我自己走过的真实节奏：

时间 你大概能做到
第 1 天 跑通记账本，看懂数据流向，学会提交和回滚
第 3 天 做出第二个小工具，开始主动提”更具体”的需求
第 1 周 敢做一个五个功能的小应用，会拆步骤
第 2 周 心里有数了：哪种代码要小心（权限、删数据、生产环境）

第二周不是你变强了，是你变懂事了 —— 知道哪些能让 AI 干，哪些必须自己盯着。

最后

Vibe Coding 真正缩短的，不是”编程的门槛”，而是从想法到能跑的 Demo 的距离。它让更多人有能力把脑子里的东西变成屏幕上能跑的东西。

但那条线一直在：谁提交，谁负责。 AI 负责写，你负责它写得对不对、安不安全、出事能不能滚回去。

工具会换，这条线不会。
