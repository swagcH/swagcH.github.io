# 2025 年 AI 入门与 Vibe Coding 文章设计

## 写作目标

为博客补齐 2025 年内容，用七篇文章记录程序员从理解大模型到建立 AI 编程工作流的过程。内容不追逐工具清单，也不把 AI 描述成自动交付软件的黑盒，而是持续回答三个工程问题：输入怎样影响结果、输出怎样被验证、责任最终由谁承担。

## 差异化约束

- 七篇文章不复用固定的“背景、问题、方案、总结”目录。
- 篇幅从约 2500 字到约 5000 字不等，代码块、表格和列表密度也有区别。
- Java 示例默认兼容 JDK 8，关键判断说明为什么这样处理。
- 案例中的项目名、接口、数据和耗时均使用演示或脱敏信息，不写真实密钥和内部地址。
- 涉及 AI 生成代码时，必须包含测试、差异审查、安全检查和回滚意识。
- 每篇提供独立封面，保持首页最新文章列表的视觉完整性。

## 验收标准

- Hexo 能解析七篇文章，文章总数由 70 增加到 77。
- 归档页显示 2025 年七篇，日期顺序正确。
- 搜索索引可以检索 Token、Context Engineering、Vibe Coding 和 Java 重构等关键词。
- 七篇标题结构、正文篇幅和阅读节奏存在明显差异。
- 桌面端和 390px 移动端无页面级横向溢出，长代码块可以横向滚动。
