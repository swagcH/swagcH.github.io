# 2020、2021、2023 年文章差异化扩写设计

## 总体目标

保留 30 篇文章的标题、发布日期、分类和线上 URL，解决 2020、2021 年文章篇幅过短、结构重复，以及 2023 年五篇文章同属排障模板的问题。扩写不是简单追加段落，而是让三个年份形成清晰的成长轨迹：2020 偏工程基础与团队协作，2021 偏真实故障定位，2023 偏系统化诊断和方法升级。

## 统一约束

- Java 代码默认兼容 JDK 8，关键逻辑添加中文注释。
- 不写真实密码、Token、客户信息或内部地址。
- 高风险命令必须说明前置条件、影响和替代方案。
- 技术教程包含验证步骤，故障文章保留证据链，协作文章给出可执行模板。
- 文章间不复用相同的一级结构和固定总结段落。

## 验收标准

- 30 篇 Markdown 均能被 Hexo 解析，原 URL 不变化。
- 文章字数、标题数量、代码块密度存在合理差异。
- 搜索索引保持 70 篇，2020、2021、2023 年归档分别为 15、10、5 篇。
- 桌面端和 390px 移动端无页面级横向溢出。
- 线上页面、动态归档和扩写关键词搜索均验证成功。
