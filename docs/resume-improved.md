- 负责 9 个异构系统的数据对接，保证数据准确性与实时性

### 医院电子通行证系统 ｜ 后端主程 ｜ 2022.03 - 2024.04

**项目描述**
管理医院出入人员并与门禁闸机联动的系统，支持读取、保存、分析通行记录，提供实时访客记录、门禁管理与授权管理功能，已被十余家医院采购并投入使用。

**技术栈**
SpringCloud · RabbitMQ · ShardingSphere · ElasticSearch · Redis · Nginx · MySQL

**我的职责**
- 核心需求分析评审，把控项目整体进度
- 独立负责出入记录、门禁管理等核心模块的设计、开发与维护
- 基于 ShardingSphere 实现自动分库分表，提升数据库性能与可扩展性
- 使用 RabbitMQ 解耦人员服务与设备模块，提升系统响应速度
- 基于 Redis 缓存用户登录信息与字典数据，降低数据库压力
- 对接微信公众号、阿里云短信实现业务消息预警

**技术难点与解决**
- **高频写入 + 时间范围检索**：通行记录是典型的高频写入场景，单表很快到达瓶颈。采用 ShardingSphere 分库分表，分片键与时间维度结合，保证"按人查"和"按时间查"两类主要查询都能有效路由
- **服务间强耦合**：人员服务与设备模块原先直接调用，一方异常会影响另一方。引入 RabbitMQ 做异步解耦，提升整体可用性
- **热点数据重复读**：登录信息、字典等高频读取数据放入 Redis，显著降低数据库压力

**量化规模**：十余家医院在用 · 门禁设备联动 · 高频通行记录写入

**技术栈**
SpringBoot · MySQL · Redis · MinIO

**我的职责**
- 核心需求分析与进度把控
- 独立负责病案借阅、封存模块的设计、开发与维护
- 使用 MinIO 进行文件对象存储，提升上传下载速度与并发能力
- 基于 Redis 对用户下载次数进行监控，防止恶意重复下载
- 对接微信公众号、阿里云短信实现消息推送与预警

**技术难点与解决**

- **数据安全与合规**：病案属于敏感数据，借阅场景存在恶意重复下载风险。基于 Redis 记录并限制用户下载次数，同时保证正常业务不受影响
