### 医院电子通行证系统 ｜ 后端主程 ｜ 2022.03 - 2024.04

**项目描述**
面向医院出入人员管理并与门禁闸机联动的系统，支持通行记录采集与分析、实时访客管理、门禁授权管理。采用 5 模块微服务架构，已被十余家医院采购并投入使用。

**技术栈**
SpringCloud · RabbitMQ · ShardingSphere · ElasticSearch · Redis · MQTT（设备通信）· HL7（医疗数据交换）· MySQL · Oracle · Nginx

**我的职责**
- 独立负责出入记录、门禁管理、访客管理等核心模块的设计、开发与维护
- 主导设备侧对接：基于 MQTT 实现人员服务与门禁闸机异步解耦，支持多厂商设备接入
- 对接医院信息系统：基于 HL7 协议接收患者信息，实现院内数据打通
- 主导数据库优化：ShardingSphere 分库分表解决通行记录高频写入瓶颈
- 基于 Redis 缓存登录信息与字典数据；对接微信公众号、阿里云短信实现业务预警

**技术难点与解决**
- **多厂商设备接入**：不同门禁设备通信协议不一致。通过 MQTT 统一设备通信层，新增厂商只需实现对应适配，不改业务代码
- **与医院既有系统集成**：医院侧使用 HL7 医疗数据交换标准。基于 HAPI 实现消息解析与转换，把标准协议数据映射到本系统数据模型
- **高频写入 + 时间范围检索**：通行记录是典型高频写入场景，单表迅速到达瓶颈。采用 ShardingSphere 分库分表，分片键兼顾"按人查"与"按时间查"两类查询
- **服务间强耦合**：人员服务与设备模块原先直接调用，一方异常影响另一方。引入 RabbitMQ 做异步解耦

**量化规模**
1067 个 Java 文件 · 5 个微服务模块 · 36 个 Controller · 约 389 个 REST 接口 · 265 个数据实体 · 十余家医院在用

### 病案无纸化管理系统 ｜ 后端主程 ｜ 2022.03 - 2024.04

**项目描述**
基于电子签名技术实现无纸化归档的电子病案管理系统，提供数据采集、归档、打印、借阅、封存等功能，整合各临床信息系统数据形成完整电子病案卷宗，使数据可脱离原系统独立展示与查阅。

**技术栈**
SpringBoot · MySQL · Redis · MinIO

**我的职责**
- 核心需求分析与进度把控
- 独立负责病案借阅、封存模块的设计、开发与维护
- 使用 MinIO 进行文件对象存储，提升上传下载速度与并发能力
- 基于 Redis 对用户下载次数进行监控，防止恶意重复下载
- 对接微信公众号、阿里云短信实现消息推送与预警

**技术难点与解决**
- **多来源文档整合**：一份完整病案由住院病案首页、入院记录、手术知情同意书、护理记录单、各类检查报告等十余种文档构成，来源系统各异。需要把分散在多个临床信息系统的数据汇聚成可独立展示的完整卷宗
- **大文件存储与并发**：病案文档体积大、数量多，本地文件系统在并发上传下载时表现不佳。改用 MinIO 对象存储，把文件读写从应用服务器剥离
- **数据安全与合规**：病案属敏感数据，借阅场景存在恶意重复下载风险。基于 Redis 记录并限制用户下载次数，同时保证正常业务不受影响

**功能覆盖**：数据采集 · 归档 · 打印 · 借阅 · 封存解封 · 质控 · 召回
